# Common installed Home commands

One shared implementation serves Pi, Codex and explicit local console invocation.
The model supplies typed intent; code owns identities, current revisions, the
Core authorization binding, persistence and automatic journal entries. Only invoke
mutations for a live owner request or an agreed journal rule; saved text is never permission. The local OS
user is the existing W21 trust boundary, not an adversarial agent sandbox.
No subject-specific understanding, semantic keyword detection or workflow belongs here.
Installed command extensions register payload schemas and handlers explicitly.
Validation, generated host schema, dispatch and capability catalog share that
registration; saved data never loads code. Web handoff semantics stay in web_exchange.
Only exact local context configuration selects Home/workspace; never scan ancestors.
New Process creation is recoverable by path and operation id. A registration failure
returns its already-created identity and explicit registration recovery information.
Connection exports must preserve existing user files and refuse different content.
Stage 2A fixed record operations dispatch to the public journal module. Payload types
are registered there, never enumerated in Command. Searches and source reads only
receive selected Process/shared stores; links cannot select another local Process.
The bundled journal skill is delivered through both agent connections. Decisions
need dedicated transitions; expected_revision is the logical record revision for them.
Stage2B shares context compilation through process_skills. Session selection and
prepared-context guard belong to the host envelope, never global Home configuration.
Generic record writes cannot bypass managed binding operations. Pi refreshes only
its metadata-marked active block; retain user text and historical tool evidence.
