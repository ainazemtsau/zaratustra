# Zaratustra — описание приложения для внешнего обсуждения

Основа: поставка 0.19.0, Core v0.1. Это повторно используемое описание продукта,
не журнал разработки, не данные владельца и не снимок его текущей установки.
Версия файла важна: опубликованный GitHub и локальная разработка могут различаться.

## Назначение

Zaratustra — open-source приложение для организации длительных направлений работы,
конкретных задач и сохраняемого знания с участием человека и программных агентов.
Оно сохраняет происхождение материалов, версии результатов и историю действий,
отделяя подготовку, исполнение и принятие результата.

## Основные понятия

Общая и Activity-память имеют единый каталог, пакетное чтение, историю и
проверяемые текстовые подборки. Кэш проверяет новые совпадения и изменения прав;
экспорт сохраняет точные версии и происхождение. Полная область включает оригиналы
и историю, сводка запрашивается отдельно. Личные сведения остаются в Core пользователя.

- **Activity** — продолжающееся направление с целью; выполнение одной задачи его
  автоматически не завершает.
- **Work** — конкретная работа внутри Activity: цель, ограничения, ожидаемые
  результаты, состояние и отдельная приёмка. Work может состоять из дочерних работ.
- **Method** — версионированный способ выполнения работы, включая составной процесс.
- **Artifact** — адресуемый результат с точной версией и содержимым.
- **Source** — неизменяемый оригинал фактически полученного материала. Оригинал
  переносимого резюме не является дословным оригиналом всей невидимой беседы.
- **Claim** — утверждение с основаниями и обозначенным познавательным статусом.
- **Analysis** — отдельный разбор источников с выводом и оставшимися вопросами.
- **Handoff** — подготовленный документ с точными основаниями; подготовка,
  сообщение об отправке, доставка и возврат различаются.
- **Decision** и **Grant** — соответственно предметный выбор и право на действия.
  Текст предложения в чате не создаёт ни того, ни другого.
- **Sleep / Change** — отдельный разбор накопленного опыта и контролируемое изменение;
  не название любого обсуждения или настройки сервиса.

## Устройство

Один SQLite Core хранит предметное состояние, права, операции, адресные ревизии
и квитанции. Сохраняемые байты управляются Core. Прямое редактирование базы не
является поддерживаемым способом интеграции. Техническое состояние длительного
исполнения DBOS отделено от предметной базы; это не второй источник решений.

Обычный локальный интерфейс — команда `zaratustra`, запускающая Pi из PATH.
`zara-core` сохраняет совместимый вход для обслуживания. Расширение обращается к
локальному Bridge, а тот — к публичным операциям Core. Назначенное исполнение
работы использует обычный Pi RPC и DBOS; агент не становится владельцем прав.
Программа, пользовательская конфигурация, пространство Core и рабочая папка
разделены. Код продукта не должен содержать частные материалы экземпляров.

Сохраняемые операции проверяют текущие права, версии, основания и допустимость
перехода. Результат выполнения и приёмка владельцем — разные события. Есть
публичные средства чтения, поиска, резервирования, восстановления и удаления.
Старый Home/file-first код сохранён как история, но не является вторым текущим
backend. Команды старой линии `zara`/`zara-agent` не заменяют текущий `zaratustra`.

## Интеграции в этой поставке

`zaratustra.integrations` — независимая от Pi/CLI граница подключаемых операций.
Каталог перечисляет только установленные реализации, контракт задаёт внутренние
аргументы, выполнение вызывает адаптер с текущей локальной authority. Возможности
заданы кодом; темы обсуждения, цель пользователя и текст инструкции не зашиты.

Поставляется ручной адаптер: сохранить индивидуально подготовленную инструкцию
или контекст, принять произвольный UTF-8 текст, читать сохранённое частями,
получить это описание продукта. `zara_integration` и CLI `zaratustra integration`
дают общий доступ к этим операциям; прежний `zara_transfer` и CLI `exchange`
сохраняют удобный путь импорта выбранного файла и старого простого prepare.

Общий агентный сценарий `zaratustra-external` помогает выяснить возможности
конкретного сервиса, подготовить настройки Activity и найти их после перезапуска.
Он не выполняет сам по себе авторизацию во внешнем аккаунте. Настройка хранится
в Core как документы и разбор с основаниями, а не в глобальном skill.

Автоматические API-коннекторы Trilium, GitHub, браузерные роботы и фоновые отправки
этой поставкой не реализованы. Описание желаемого workflow не запускает его.
Будущий внешний эффект требует реализации адаптера, прав, устойчивого учёта
отправок и обработки повторов/неопределённых результатов. Ручной путь не ограничивает
будущие адаптеры ручным режимом.

## Как обсуждать идеи

Сначала сопоставляйте предложение с целью выбранной Activity и текущими механизмами.
Не считайте любую идею поручением реализовать код. Различайте проверенное поведение,
документированный замысел, предположение и предложение. Проверки и ограничения
называйте по фактическим основаниям, не по уверенности ответа.

Если нужны точные детали, запросите у Code Agent конкретные файлы, интерфейс или
наблюдение. Он может подготовить материал, который пользователь перенесёт сюда.
Нет необходимости требовать полный репозиторий или историю бесед ради одного вопроса.
Неизвестные данные не восполняются придуманными именами, датами или идентификаторами.

## Чтение репозитория и ограничения доступа

Публичный репозиторий: https://github.com/ainazemtsau/zaratustra

Если в вашей среде действительно есть разрешённое чтение репозитория, зафиксируйте
прочитанную ветку/commit. Не предполагайте, что публичный main равен локальной версии.
При доступе к GitHub основной источник меняющихся сведений — актуальная выбранная
ветка репозитория. Не требуется отдельный файл контекста Project или его ручное
обновление после изменения кода. Начинайте с README и доступных документов
репозитория; затем читайте только относящиеся к вопросу файлы:

- `src/zaratustra/foundation/` — Core, предметные модели, права, память и исполнение;
- `src/zaratustra/integrations/` — общая граница интеграций и ручной адаптер;
- `src/zaratustra/pi_adapter/` — подключение обычного Pi;
- `src/zaratustra/release.py` — установленный CLI;
- `tests/zaratustra/` — проверки соответствующих модулей;
- `docs/core-v0.1/Zaratustra_Core_Specification_v0.1.md` — утверждённая спецификация.

Спецификация не доказывает реализацию каждой возможности. Старые планы и отчёты
не подменяют текущее поведение. Отсутствующий в опубликованной ветке файл не
восстанавливайте догадкой: используйте приложенную версию или запросите её у агента.
Чтение GitHub не даёт доступа к локальному Core, частным файлам или права писать
в репозиторий. Для исходного ручного сценария достаточно чтения и подготовки текста.

Если GitHub недоступен, используйте этот файл и явно предоставленные дополнения.
Не объявляйте документ автоматически свежим: сверяйте версию при существенных
изменениях. Данные конкретной Activity добавляются отдельно и только в выбранном
для передачи объёме, без секретов и несвязанных личных материалов.
