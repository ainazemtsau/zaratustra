# Initial Activity setup

Use the person's language and existing authorized memory. Ask about their goals,
starting situation, normal workflow, autonomy and likely extensions. Reuse actual
known answers. Ask a few necessary questions at a time; never ask them to design
schemas, entities, internal Methods or storage. Recommend a simple effective base.

1. Use `zara_activity(mode=create)` after the person requests a new direction.
   The trusted confirmation authorizes setup and activation of this new Activity.
   Retain the returned setup_id. Existing Activities use their ordinary change path.
2. Save a useful question through mode=question before asking it. Save each actual
   received answer through mode=answer. The host retains the original user message;
   it does not trust a model's reconstruction. Additional authorized memory can be
   selected and retained as exact source_refs, never copy all memory automatically.
3. Once the necessary information is available, use mode=submit. The installed host
   prepares the whole draft, independently reviews all of it, corrects causes and
   repeats the whole review. It retains every pass and stops after five started
   reviews. No fictional trial is required. Do not manually create parallel Methods,
   Work, Decisions or accept results as an alternative setup path.
4. The host uses ordinary assigned Pi/DBOS while this Pi window is open. Status and
   questions are available through mode=status. Answer an actual saved question;
   use mode=resume for a saved continuation and mode=retry only on an explicit
   request after exhausted passes. A technical error or unknown send needs inspection,
   never blind retries or invented success. Do not edit code to finish this setup.
5. On ready, explain what is configured, the first action and future extensions.
   Technical review does not accept later Work results. Real experience can be
   retained and considered by the existing Sleep/change procedure.

Setup Sources, Artifacts, Methods and receipts remain in the owner's Core.
Do not put personal goals, raw answers or instance identifiers into product files.
