# Useful bounded Sleep

Use zara_sleep start/resume/status/cancel, or the native /zara-sleep command. The same
approved provider/model/thinking and native authentication are used; no second mandatory
reviewer, daemon or extra launcher. Speak the user's language; canonical memory is English.

Start only on the user's explicit request. Discover an existing cycle first. One workspace
has one active review; unrelated work and agents keep running. A new cycle selects up to10
meaningful cases: repeated/open problems, real corrections, useful episodes, contradictions
or obsolete conditions. Do not enumerate every revision or routine successful tool output.
Legacy start_sleep/sleep_checkpoint are historical compatibility, not the schema10 procedure.

The controller enforces select -> read/analyze -> propose -> validate -> apply -> future check
-> finish. Tools can prove source delivery, not understanding. Read enough exact bodies,
conditions and counterexamples. Cards alone do not prove a hypothesis. Group repeated cases;
no-change and insufficient evidence are valid. Do not manufacture improvements or busywork.

Each finite proposal identifies the concrete problem, exact read premises, proposed changes,
expected benefit, risks and the next real observation that could refute it. Keep observed,
reported, inferred, applied and benefit-confirmed distinct. A correlation between activities
is tentative until supported; missing logs do not prove a missed activity.

Automatic changes stay inside the configured reversible delegation: supported local structure,
exact duplicate consolidation and Activity-bound procedures. A relevant Activity origin alone
does not grant ownership. Goals, significant commitments, rights, identity merges, destructive
purges, code installation and external effects require their actual existing authority. Never
simulate a native human confirmation, change provider or bypass refusal via shell.

Budget: up to10 cases,3 logical improvements,20 logical model generations or15 minutes,
whichever comes first. The native stream delegate is gated before invocation. No transcript
is durably saved. Restart does not reset budget; after exhaustion only an explicit new cycle
may spend a new budget while preserving cumulative accounting and a useful continuation.
A final hidden model summary beyond budget is forbidden; report exact persisted state.

A completed review is not proven usefulness. Applied changes need an addressed future check
on suitable ordinary work. Keep negative outcomes, narrow or roll back a bad procedure, and
leave unknown matters open. Sleep's own checkpoints/status/summary are not new life experience.

Use zara_sync status for actual private GitHub persistence; local save is not remote save.
Restore requires current-world reconciliation before potentially repeating external actions.
