# Sleep through ordinary conversation

Use the SAME extension/Core and the user's selected Pi model. Speak the user's language;
write working content in English and preserve original sources. Start only on an explicit
review request. Default scope is all permitted workspace memory. An explicitly requested
Activity has independent coverage. No launcher, scheduler, daemon, code installation,
provider switch, extra AGENTS file or second executor is needed.

First call zara_sleep_batch with no arguments to discover an interrupted review. Resume its
exact prepared batch and its existing running episode; reading old cases is not another
Method invocation or success. Core rejects invoke_method on Sleep Runs; subsequent suitable
ordinary work records actual applications in its own Run. A fresh process needs no previous transcript. Discover lost
replies through operations/Changes/receipts and actual targets. Never guess a replacement
commit from a similar title. An identical request replay returns its receipt; a changed
payload needs a new request ID after re-reading.

For a NEW explicitly requested cycle create ordinary Work and start_run mode:sleep, with
that Work's ref, in zara_commit; include start_sleep with work_ref and run_ref. Existing
Work/Run bindings need guards. A global Work has activity_id:null; do not create an artificial
Activity. An Activity review binds its Work.activity_id to the exact Activity. Core derives
the frozen scope from this authoritative Work binding and permissions from trusted context;
no input cursor, high-watermark, access profile or source authority is a model argument.
Use a meaningful unique episode_key. start_sleep freezes retained eligible history and its
first batch. A different access profile or restored epoch needs an explicitly requested
new review; an old profile's cursor must never hide newly accessible old material.

Read zara_sleep_batch with run_id for ten stable routing cards and exact source refs. Read
selected bodies, original goals/results, exact Method versions, Evaluations, grounds and
current conditions via existing zara_read/addressed ranges. Cards are routing data. No
hidden fact, body summary or card implies an actual owner judgment. RPC, quoted/imported
feedback and synthetic controllers use reported_feedback; ordinary interactive input is
observed-stage unless a trusted ingress establishes more. Keep observation distinct from
causal hypothesis. No custom keyword planner, translator, causal classifier or second model.

Checkpoint every prepared item once with zara_commit sleep_checkpoint: run_ref, batch_id,
dispositions. Each disposition includes item_id, disposition (considered/changed/deferred),
reason, continuation, evidence_refs, change_refs, expected_benefit, limits, next_check and
check_signal_ref; use null/[] where inapplicable. Guard the CURRENT revision shown for every
member and any other material premise. A stale guard requires re-reading and a rebuilt
request; progress has not advanced. The exact batch has no caller-selected positions/skips.
The checkpoint atomically saves corrections, dispositions, deferred anchors, next batch,
Changes and receipt. Keep calls within normal validation bounds; there is no total limit
on batches, reads, attempts, continuations, tokens, money, cases or elapsed time.

Every disposition's evidence_refs accepts only retained Evidence records. Method/Run refs
are read premises or change_refs, not Evidence; keep evidence_refs empty for a considered
item unless it cites actual retained source Evidence. A changed disposition still requires
Evidence grounds as well as exact changed refs. Core rejects mixed kinds without progress.

An unchanged item may remain unknown or open. A deferred item needs a concrete reason,
addressed continuation and next_check condition. Pending approval may be deferred while
independent work continues; deferred never means resolved. For changed items retain source
Evidence, exact change_refs from the SAME checkpoint, expected benefit, limits/regression
risk and later real check trigger. Open/review an ordinary Signal in that checkpoint and
reference it as check_signal_ref. Small grounded global Knowledge/textual Method corrections
use existing rights. Exact Method content versions remain distinct from technical revisions.

In Activity mode only explicitly bound Work/Run and their unambiguously local operational
records may change automatically. Knowledge and Methods remain SHARED even when their
origin_activity_id, classification or prose mentions this Activity. Shared/mixed/ambiguous
changes require zara_preview of the EXACT checkpoint request, zara_confirm through the native
dialog, then the identical commit plus preview_ref. Goal/acceptance/priority changes,
identity merges, bulk reorganization, archive/deletion and external effects retain their
existing native exact approval requirements. Sleep grants no new rights. Never use shell
or another tool to bypass a refusal.

Use a changed Method in subsequent SUITABLE real work with its actual selected_versions,
an ordinary non-Sleep Run/invocation and separate technical, reported/model and actual owner
assessments. A method edit, review or invocation alone proves no improvement and cannot
resolve the Signal. Preserve unsuccessful improvements and negative evidence; revise,
narrow or compatibly roll back when grounds warrant it. Missing grounds stay unknown.
An empty/no-new-ground review invents no case, result, fact or mandatory improvement.

Each review is finite by its frozen INITIAL membership, never by resource exhaustion. New
arrivals wait for the next explicitly requested cycle. Continue prepared batches until
completed; do not self-start another cycle. sleep_checkpoint abort:true preserves committed
work and explicitly ends this cycle after disposing the current batch; remaining material
is reconsidered by a later explicitly requested review. Do not recursively mine Sleep
Work/Run, checkpoints, review summaries or Signal-review bookkeeping as fresh experience.
Substantive corrections stay addressed; later real checks remain ordinary open Signals.

Finish the episode and ordinary Work through existing lifecycle rules when appropriate.
Preserve minimal exact grounds pinned for pending batches/deferred work/checks. Restore
retains old progress but invalidates continuation in a new epoch: explicitly create a new
review over restored retained history. Sleep never clears E3 reconciliation/unknown effects.
Report actual committed coverage, remaining addressed deferrals and limitations through chat.
