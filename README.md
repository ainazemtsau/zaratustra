# Zaratustra

Текущий вход в этой ветке — **обычный Pi с расширением Zaratustra**, пакеты
`zaratustra-core` и `zaratustra-next` версии **0.2.0**. Это проверяемый кандидат;
окончательная техническая проверка и живой рабочий цикл ещё выполняются.

Точный сохранённый пакет, SHA и текущие ограничения приведены в
[индексе поставки](delivery/README.md). Это checkpoint **NOT_READY**: согласованное
продолжение Sleep и итоговая проверка ещё выполняются. Для пробной установки
распакуйте указанный ZIP в постоянную папку и зарегистрируйте извлечённый каталог:

```text
pi install "/absolute/path/to/extracted-package"
```

Затем откройте обычный Pi в нужном репозитории, введите `/zaratustra` и опишите
задачу обычными словами. Ежедневный PowerShell-скрипт не нужен. Pi ведёт диалог,
вызывает модель и работает своими инструментами; отдельное ядро хранит Activity,
историю и результаты. В обычной работе нет искусственного лимита вызовов модели.

[Инструкция текущего расширения](pi-package/README.md) описывает prerequisites,
первый запуск, `/reopen`, Sleep, отдельную проверку и явный вердикт владельца.
Сборка поставки из исходников:

```text
uv sync --locked
uv run --locked python -m tools.build_permanent_package --output delivery/zaratustra-pi-0.2.0
```

Папка данных находится вне репозитория и поставки. При обновлении в новую папку
Pi требует убрать регистрацию старого пути через `pi remove` и установить новый
через `pi install`, затем перезагрузить расширение; одинаковое имя пакета само
не заменяет старую регистрацию. Точные команды внутри Pi приведены в инструкции
расширения выше. Совместимое обновление кода сохраняет Activity, историю,
ожидающие вопросы и точные ссылки без повторной инициализации. Восстановление, синхронизация между компьютерами и загрузка личных
данных в GitHub не входят в текущий минимальный путь. Проверки Windows и
переносимость Python/TypeScript не выдаются за фактическую проверку на macOS.

## Прежняя реализация — историческая инструкция

Ниже сохранено описание прежней реализации и её проверок. Команды `zaratustra
setup`, DBOS, пакет 0.25.0 и Pi 1.0.4 относятся к ней, а не к текущему входу выше.

Zaratustra — open-source продукт для длительных направлений работы, конкретных
задач и сохраняемого знания с участием человека и программных агентов.
Прежняя основа — **Core v0.1 / Activity**, версия пакета — **0.25.0**.

Один SQLite Core хранит предметные данные, права, адресные версии и квитанции.
Activity задаёт направление; Work — конкретную работу; Method — версионированный
способ исполнения. Source сохраняет полученный оригинал, Analysis — отдельный
разбор, Claim — утверждение с основаниями, Artifact — результат. Подготовка,
исполнение, внешняя доставка и приёмка владельцем — разные события.

Обычный локальный вход — `zaratustra`, использующий установленный пользователем
Pi из PATH. Назначенное исполнение использует тот же Pi RPC и DBOS; DBOS хранит
техническое состояние, а не вторую предметную базу. Старый Home/file-first backend
сохранён в истории, но не подключается как параллельный источник состояния.

## Установка и запуск

Разговор ведёт один основной агент Pi. Создание Activity и запуск процесса ждут
сохранённого результата, вопроса или препятствия и возвращают его тому же агенту.
Исполнители и индикаторы состояния не запускают отдельные ответы. При повторном
входе попросите продолжить работу: сохранённые ответы и результаты остаются в Core.

Проверенный контур: Windows, Python 3.13.7, Node 22.19.0, SQLite 3.53.3 и Pi 1.0.4.
Это граница фактических проверок, а не обещание проверки всех платформ и будущих
версий Pi. Программа, её конфиг, Core и рабочая папка выбираются отдельно.

Собрать wheel из этой ветки:

```text
uv sync --locked
uv build
uv tool install --force --from dist/zaratustra-0.25.0-py3-none-any.whl zaratustra
```

Для новой установки подготовьте обычный Pi и выполните `zaratustra setup`.
Выберите личную папку, существующий или новый Core и необязательный приватный GitHub.
[Пространство и проекты](docs/workspace.md) описывает разделение папок и сохранение.
Подробные параметры: [runbook](docs/core-v0.1/INSTALLED-RUNBOOK-20260927.md).
Если конфиг уже существует:

```text
zaratustra bind --config <path-to-config.json>
zaratustra verify
zaratustra
```

После `CONNECT` доступен обычный разговор и инструменты Core. Ассистент может
выбрать существующую Work по вашему сообщению; `/zara-work` остаётся ручным выбором.
Сохранённый разговор открывается через `/resume`.
Можно переопределить модель на один запуск: `zaratustra --model <model-id>`.
Доступные модели и провайдер зависят от собственной настройки Pi и аккаунта.
Секреты не помещаются в репозиторий, Project Instructions или материалы Core.

Версия 0.19.0 добавляет [общую память](docs/general-memory.md): каталог областей,
пакетное чтение, историю, проверяемый кэш и полный текстовый экспорт. При обновлении
существующей установки выполните `zaratustra upgrade` для явного перехода к схеме 18.
Личные сведения остаются в пользовательском Core.

Уже выбранную установку не нужно повторно `setup`/`bind` при обновлении wheel:
завершите процессы Zaratustra, обновите существующий uv tool, выполните `verify`
и запустите новый процесс. Windows может блокировать замену занятого launcher.
`upgrade` мигрирует схему Core, а не обновляет программу. Не пересоздавайте Core
ради замены программы. Обычный Pi обновляется отдельно от Python-пакета.

## Настройка новой Activity

Версия 0.24.0 возвращает завершение настройки и других процессов в обычный
разговор Pi. Ассистент получает проверенное состояние Core, объясняет результат
и предлагает следующий шаг. Для существующего Core нужен явный переход к схеме 18;
команда сохраняет проверенную резервную копию перед обновлением.
После закрытия Pi можно спросить «что дальше?»: состояние и результаты остаются
в Core. При нескольких процессах ассистент предлагает выбрать нужный.
Служебное уведомление не считается ответом пользователя, а сообщение о готовом
результате не принимает Work автоматически. См.
[продолжение разговора](docs/conversation-continuation.md).

Версия 0.23.0 добавляет [общие workflow и сохранённое продолжение](docs/workflows.md).
Версия 0.23.1 ограниченно повторяет чтение статуса при временной занятости Core
и передаёт точный контракт публикации результата выбранной Work. Ошибки
указывают поля результата; сохранение и принятие Work остаются отдельными.
Для существующего Core требуется явное `zaratustra upgrade` до схемы 16.
Версия 0.23.2 исправляет порядок этой команды: после подтверждения и проверенной
резервной копии она выполняет миграцию, затем разрешает обычный запуск Pi.
Версия 0.23.3 различает паузу, остановку исполнителя и неизвестный исход запроса.
Дополнения сохраняются отдельно от ответа на вопрос. Прерванный этап сохраняет
историю и расход; при неизвестном исходе новая подготовка требует явного
подтверждения и новых оснований, без повторной отправки прежней Work.
Начатые Work, история и принятия сохраняются. Ассистент связывает ответы с
вопросами, объясняет остановки и проводит полное ревью перед включением.

Версия 0.22.0 добавляет [общие структуры данных и процедуры](docs/activity-structures.md).
0.22.1 исправляет сохранение и ограниченное исправление ошибочных ответов настройки
до ревью; схема остаётся 15. См. [настройку Activity](docs/activity-setup.md).
Ассистент проектирует процесс и записи под цель пользователя. Обязательных
шаблонов Health или Development нет. Ревью проверяет весь скомпилированный пакет.
Прежняя Activity может получить структуру без пересоздания; старые Work сохраняют
свои основания и версии.

В обычном Pi опишите направление: «Создай Activity для …». Ассистент сохраняет
запрос, задаёт необходимые вопросы о вашей работе и после ответов самостоятельно
готовит настройку. Полное ревью, исправления причин и повторное полное ревью
проходят в отдельных назначенных Work. Успешная актуальная настройка включается
автоматически; принятие результатов последующих Work остаётся вашим действием.
Прогресс и пять начатых проходов ревью сохраняются между сессиями.
Статус без модельного запроса: `/zara-setup`. [Подробности](docs/activity-setup.md).

## Внешнее обсуждение и GitHub

При доступе внешнего чата к GitHub **основной источник меняющегося кода — репозиторий**:
https://github.com/ainazemtsau/zaratustra . Используйте актуальный `main` или явно
выбранную ветку. Постоянные Project Instructions содержат правила и маршрут чтения,
не копию текущего кода. Обязательный файл контекста Project и его ручное обновление
после изменений репозитория не нужны.

Начинайте с README, [руководства по интеграциям](docs/integrations.md) и относящихся
к вопросу файлов. Называйте действительно прочитанную ветку/commit, когда они известны.
GitHub не показывает неопубликованные изменения и локальные данные экземпляра.
При конкретном недостатке сведений внешний чат формулирует вопрос Code Agent;
пользователь переносит запрос и полный ответ. Текст/файл — запасной путь при отсутствии
доступа или для отдельных локальных сведений, а не обязательный журнал Project.

## Реализованный слой интеграций

`zaratustra.integrations` — общая граница установленных технических операций,
независимая от Pi и CLI. Каталог и контракты точны; пользовательские темы и цели
не ограничены списком. `zara_integration` доступен в обычном Pi; без модели:

```text
zaratustra integration catalog
zaratustra integration contract --adapter manual --operation prepare_document
```

Первый адаптер — **manual**: сохранить готовую индивидуальную инструкцию/контекст,
сохранить полный доставленный текст, прочитать точную ревизию окнами, получить
поставляемый обзор продукта. Обзор — дополнительный источник, не живой Core и
не обязательное приложение к Project. Существующие `zara_transfer` и `exchange`
сохраняют совместимость.

Skill `zaratustra-external` поставляется вместе с wheel и явно загружается launcher.
Настройка и история конкретной Activity остаются в Core, не в общем skill или docs.
Произвольный текст, отсутствующая дата и невалидный JSON внутри него не блокируют
сохранение. Сначала сохраняется оригинал, затем отдельно разбор и дальнейшие действия.

Подготовленный Handoff не означает отправки; сохранённый Source не означает факта,
разрешения исполнить предложение или acceptance Work. Автоматические API-коннекторы,
Trilium, браузерные роботы и фоновые внешние отправки пока не реализованы. Чтение
GitHub средствами внешнего чата не является новым API-коннектором Zaratustra.
Подробнее: [интеграции](docs/integrations.md).

## Разработка и проверки

Начните с [AGENTS.md](AGENTS.md),
[спецификации](docs/core-v0.1/Zaratustra_Core_Specification_v0.1.md) и
[политики выпуска](docs/core-v0.1/DELIVERY-POLICY-20260926.md).
Текущий результат и ограничения: [RESULT.md](RESULT.md).

```text
uv run --locked python -m tools.check --deliver
```

На Windows закреплённый SQLite runtime можно передать через `ZARATUSTRA_SQLITE_DLL`.
Полный gate проверяет hygiene, типы, импортные границы, тесты и сборку. Обычные Pi
traces используют localhost и синтетический провайдер; они проверяют механические
пути, не качество реального ответа модели или настройку внешнего аккаунта.
Публичная ветка не содержит новых частных отчётов экземпляра и не публикует его Core.
