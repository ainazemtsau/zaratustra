# Общая память

Общая память поставляется с Zaratustra 0.19.0. Она использует то же пространство
Core, что Activity, Work и результаты. Отдельной базы профиля нет.

## Как пользоваться в Pi

После обновления программы выполните `zaratustra upgrade`, затем запустите
`zaratustra`. Обновление схемы 12 → 13 явно; обычное чтение его не выполняет.
Для новой установки схема подготавливается командой `setup`.

Можно сказать агенту:

> Сохрани это как общее справочное сведение с темой «оборудование».
> Для этой задачи прочитай сведения об оборудовании из общей памяти и выбранных Activity.
> Подготовь полную память выбранной Activity, включая историю и оригиналы, и экспортируй в Markdown.

Агент определяет смысл и разметку. Core проверяет типы, адреса, права и версии.
Обычные чтения и создание разрешённых подборок не требуют подтверждения каждого
действия. Это не разрешает менять права, принимать Work или удалять данные.

`zara_memory` предоставляет:

| Режим | Что возвращает |
|---|---|
| `catalog` | Страница названий, тем, областей, новых поступлений и наличия истории |
| `read_batch` | Точный снимок объединения нескольких областей, тем или адресов |
| `history` | Страница редакций одной записи, доступность и адреса оснований |
| `open_selection` | Следующее окно текста уже сохранённого снимка |
| `prepare_cache` | Проверенный кэш: неизменный используется повторно, изменённый пересобирается |
| `export` | Полный Markdown в новом файле внутри выбранного рабочего ресурса |

Один запрос может содержать несколько `selectors`. Условия внутри одного
selector пересекаются; selectors объединяются без повторения редакций.
`common` и `activity_ids` в одном selector объединяют выбранные области.
`topics` выбирает любую названную тему; `query` использует существующий FTS.
`record_ids` адресует записи явно. Пустая подборка условий означает всю доступную
память, поэтому для обычной задачи лучше называть области или темы.

По умолчанию читаются текущие сведения, документы и новые необработанные
поступления. Разговоры и предыдущие редакции раскрываются с `full: true`.
Полная область включает точные связанные основания, даже когда исходник
принадлежит другой области. Его происхождение сохраняется. Сводка — отдельный
Analysis или MemoryView, а не подмена полного чтения.

## Большая подборка и экспорт

Результат содержит адрес `selection_id`, число редакций и частей, признаки
`selection_complete`, `assembly_complete`, `content_complete`, `restricted`
и `current`. Ограниченные права не превращаются в заявление о полной памяти
всего пространства. Явно запрошенный недоступный адрес даёт адресный отказ.

`content_complete` означает, что весь текст возвращён именно этим обращением.
`end_of_selection` означает конец чтения; последний маленький фрагмент не выдаётся
за весь текст. `returned_bytes`, `total_bytes` и границы окна показывают фактический объём.

Текст содержит заголовки с адресами редакций и JSON происхождения, включая
связанные основания. Нетекстовые оригиналы представлены base64 с типом содержимого.
Если `next_part` не пустой, продолжайте `open_selection` с `next_part` и
`next_offset`. Конец одного окна не означает получение всей подборки.
Состав фиксирован: следующие страницы не переключаются на новые редакции.

`table_of_contents` показывает страницу адресов этого точного снимка;
`next_toc_offset` продолжает оглавление через параметр `toc_offset`.
Полный Markdown содержит оглавление всех сохранённых редакций.

Подготовка частей не держит длительную транзакцию записи. Готовый корень появляется
после сохранения всех частей. Прерванная сборка с тем же operation ID продолжается
идемпотентно. Экспорт публикуется после полного чтения и повторной проверки доступа;
существующий файл не перезаписывается даже при конкурентном создании.

Снимок и его части внутри Core — управляемые производные материалы. Удаление
основания санирует их и содержащие данные резервные копии по существующим правилам.
Выданный пользователю файл — самостоятельная копия: Core не удаляет произвольные
файлы пользователя и не обновляет материал в чужом чате автоматически.

## Кэш и Method

Кэш сохраняет правило подбора, точные редакции и версию сборки. Core проверяет
совпадающие записи и новые совпадения, принадлежность областям и текущий доступ.
Служебные ContextManifest, исключённые захваты и сгенерированные части не входят
в индекс памяти. Изменение другой области не пересобирает узкую подборку.

Подборка обновляется без модели. Смысловой анализ не переписывается автоматически:
изменение его основания обозначает устаревание, новый анализ делает агент.
Новое сообщение считается поступлением; явный Claim/Analysis на его основе
обозначает обработку. Следующее новое измерение сохраняется отдельным Source,
исправление утверждения — новой редакцией Claim с новым основанием.

Новая версия Method может содержать `memory_requirements` с selectors и признаком
`required`. `current_activity: true` подставляет Activity исполняемого Work.
Назначенный Work автоматически получает проверенную подборку, её адрес и первое
окно; большой материал дочитывается инструментом. В контекст не вставляется вся
память или полный каталог. Текущие обязательные условия общей и своей Activity
доставляются отдельно от поискового рейтинга. Старые неразмеченные Claims сохраняют
прежний автоматический маршрут до явной классификации.

Method допускается через существующий Candidate/Decision; изменение версии
не заменяет Method и закреплённые входы уже созданного Work. Составной Work
продолжает исполняться через существующий назначенный Pi RPC, а обычный разговор
может явно пользоваться теми же подборками. Кэш, выбранный в разговоре через
`prepare_cache`, проверяется перед следующей отправкой. Изменение после подготовки
ContextManifest блокирует отправку устаревшего основания.

При продолжении сохранённого чата и compact адреса ранее прочитанных подборок
восстанавливаются из истории Pi. Снимок остаётся историческим, а права на исходники
повторно проверяются перед отправкой. Отозванный доступ нельзя обойти старым ответом
инструмента. Проверяемый текущий кэш и исторический снимок учитываются отдельно.

## Без модели и внешние инструменты

```text
zaratustra memory catalog --common
zaratustra memory read_batch --common --topic equipment
zaratustra memory read_batch --activity <activity-id> --full
zaratustra memory open_selection <selection-id> --part <next-part> --offset <next-offset>
zaratustra memory history <record-id>
zaratustra memory export <selection-id> --file <new-file.md>
```

Те же пять операций чтения/кэша доступны через `zaratustra.integrations` в адаптере
`memory`; Core также предоставляет экспорт. В ручном обмене явно выбранные
размеченные сведения другой Activity разрешены после проверки прав. Activity/Work
самого обмена остаются собственными основаниями, чужая работа не переносится.

Для создания сохраняемой подборки нужны `record.read` на основания и
`artifact.write` для управляемого производного материала. Каталог, история и
чтение существующей подборки не выдают новые права. Права на подборку не заменяют
прав на её источники.

Health и внешние хранилища в этот пакет не входят. Примеры вымышленные; личные
сведения сохраняются только в выбранном пользовательском Core.

## Проверки реализации

Каждый сценарий наблюдает отдельную поломку, а не текст ответа модели:

| Проверка | Наблюдаемый результат |
|---|---|
| Core `batch_union_history_and_original_scope` | Объединение без повторов; исправление сохраняет старую редакцию и область |
| `cache_reuses_then_updates_membership_without_unrelated_changes` | Неизменный кэш не пишет состояние; новая запись и перенос темы меняют состав |
| `revoked_source_access_is_not_bypassed_by_saved_selection` | Закрытый оригинал нельзя прочитать через части, экспорт или отправить из истории |
| `new_matching_input_fences_prepared_context` | Новое совпадение блокирует текущий подготовленный кэш; исторический снимок остаётся историческим |
| `partial_assembly_replay_and_unicode_export` | Прерывание не создаёт готовый корень; повтор, UTF-8 окна, binary и конкурентный экспорт сохраняют байты |
| `filtered_read_does_not_decode_unrelated_memory` | Чужие payload не декодируются; страница из двух совпадений не материализует все 40 |
| `deletion_purges_derived_selection_and_contaminated_backup` | Производные части и загрязнённая резервная копия санируются вместе с исходником |
| `upgrade_retains_old_bytes_and_cache_reopens` | Явная миграция сохраняет SHA; свежая сессия повторно использует кэш |
| `source_organization_preserves_capture_and_processed_intake` | Разметка сохраняет event и оригинал; pending-анализ не скрывает поступление |
| Pi `conversation_refreshes_cached_membership_and_fences_old_manifest` | Новая сессия восстанавливает правило; добавления видны до отправки |
| Pi `required_memory_scope_and_legacy_claim_delivery` | Обязательные общие сведения и старые Claims доставляются; чужие условия не добавляются |
| Integration `organized_foreign` | Явные чужие сведения разрешены, собственные основания обмена сохранены |

`tools.probe_memory_pi` проверяет установленный продукт с обычным Pi и локальным
синтетическим провайдером: инструменты, полный экспорт, compact, восстановление
нативного чата, чтение результата в новой сессии и назначенный Work. Реальная
модель и платный API не нужны. Фактические результаты и границы — в `RESULT.md`.
