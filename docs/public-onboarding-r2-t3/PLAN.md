## Bounded effect

This T3 joins the existing creation, entry, Process-state, Pack work-creation and
safe-change surfaces behind the installed `zara entry` path. Ordinary UTF-8 command
arguments build the already released `CreationDraft`; callers do not write JSON or
choose capability identifiers. The coordinator uses the complete installed
construction capability tuple and does not infer a domain graph, definition or
approval from prose.

The new continuation read has two truthful branches. Before activation it renders
the persisted creation stage and its next manual action. After activation it resolves
the catalog row and separately authorizes the exact Core `ProcessStateQuery`, then
renders the authoritative current/no-current Work, saved Process materials and
Results. It never selects a historical Work or writes while reading.

When Core reports no current Work, one explicit later-Work intent may be retained
beside the catalog. The retained plan contains the complete ordinary Work, exact Pack
binding, exact supplied generic definition bytes and operation identity. It grants no
authority. The trusted Pack host revalidates the exact registration before Core
creates the Work, and Core remains the only writer. A retry recovers only the exact
committed operation; a changed intent, changed definition, intervening revision,
current Work or missing/incompatible binding refuses without rebasing.

Safe change is exposed through the same installed entry path. Review opens the exact
current Core context, shows the existing complete change preview and records an
explicit local approve/reject decision. Apply separately authorizes the existing
Core Result request. Fresh-chat status/review/apply use the existing change journal
and committed Result lineage; no adapter or retained decision becomes authority.
