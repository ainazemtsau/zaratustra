# Открытые наблюдения после 2B

## Конкурентный перенос записи старого каталога

**Статус: открыто. Причина не установлена, исправление не выполнено.**
Успешный повтор не закрывает наблюдение и не подтверждает исправление.

### Что наблюдалось

В первом полном прогоне 2B тест
`tests/zaratustra/entry/test_catalog.py::test_relocation_preserves_concurrently_added_independent_row`
завершился ошибкой. Он одновременно переносит запись Alpha и добавляет независимую
запись Beta в прежний файловый каталог. При проверке результатов дочерних процессов
на строке 282 возник `KeyError: 'designation'`: в одном из результатов не было
ожидаемого поля. Исходная трасса не показывает возвращённый дочерним процессом код
ошибки, поэтому по ней нельзя установить первопричину.

[Полная исходная трасса](evidence/catalog-first-failure.log) сохранена без изменения
байтов. SHA-256:
`7d30f676431ad0daf71533a127351dc1217086dbfef06cef18f7e1b2ffb38b69`.

### Известное влияние

- Первый полный прогон остановился: 472 теста прошли, один не прошёл. До сборки
  пакета этот прогон не дошёл.
- Наблюдение относится к параллельным операциям прежнего файлового каталога
  `zaratustra.entry`. Проверка не доказала сохранение обеих успешных операций
  в том конкретном запуске.
- Потеря данных, конкретная причина отказа и влияние на другие сценарии этой
  трассой не установлены. Переносить вывод на SQLite Home без основания нельзя.
- В уже выполненном показе Pi с учебными процессами сбой не наблюдался. Это
  отдельное свидетельство и не проверка устранения причины данного отказа.

### Что произошло после

Отдельный штатный запуск через `python -m pytest` прошёл; затем прошёл второй
полный прогон с 473 тестами. Код каталога и его тест для получения этих результатов
не менялись. Две промежуточные диагностические команды через консольный `pytest`
не смогли импортировать tests в дочерних процессах Windows; это другая ошибка
способа запуска, она не объясняет исходный отказ.

### Условие продолжения разбора

При повторении или новом воспроизводимом основании сохранить оба результата
дочерних процессов, их коды ошибок и фактическое содержимое каталога до проверки.
Начать с ограниченного воспроизведения этого сценария. Новые полные прогоны без
новых оснований не требуются. Закрытие наблюдения требует объяснённой причины и
проверенного исправления либо доказанного уточнения причины вне продукта.
