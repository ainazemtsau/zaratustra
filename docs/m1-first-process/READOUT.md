# Один вымышленный процесс прошёл весь сценарий

Процесс проверяет вымышленную партию KITE и сохраняет решение о её выпуске.
Это пример для проверки расширяемости продукта, без настоящих данных и действий.

| Шаг | Что произошло через Core |
|---|---|
| Проверка | Для корпуса и этикетки нужны две отметки: проверено и записано. При отсутствии одной отметки продолжение отклонено; принятые наблюдения сохранены. |
| Исправление | Полная проверка сохранена как первый Result. Создана работа с отдельным выбором «выпустить или отклонить». |
| Основание решения | Работа получает точные сохранённые материалы проверки. Решение, ссылающееся на другие байты проверки, отклонено без изменения состояния. |
| Итог | Fictional host передал решение «выпустить» с правильным основанием. Core сохранил второй Result. |
| Завершение | Общий API создаёт continuation после каждого Result. Её явно отменили штатной операцией: это отменённая пустая Work, а не третий выполненный результат. |

В final snapshot revision 19: **2 Results, 0 доступных работ, 0 открытых решений**.
Две рабочие стадии — done, пустая continuation — cancelled. Статус внешнего
контракта: `inspect/done, decide/done, closed(release)/cancelled`.

Все семь возможностей подключены к этому пакету. На стадии выбора контракт
показывает требующее внимания решение, доступную Work и её контекст. В финале
видны два важных результата; context_requirements без выбора Work честно
возвращает `unavailable/not_requested`. Это JSON evidence одного Process;
общий обзор двух процессов ещё предстоит.

При выборе только второй Work список чужих Results пуст, но её разрешённые
унаследованные основания доступны через отдельный подтверждённый запрос контекста.
Знание требований или наличие пакета не выдаёт прав на запись. Состояние до обоих
Result сохранено, восстановлено в новые папки и повторно прошло тот же запрос.

Предметная логика лежит в `src/zaratustra/fictional_lot`. Core и общий слой
`process_packs` побайтно совпадают с принятой исходной версией. Сохранена версия
для будущего сравнения: второй процесс должен подключиться без изменения Core.
Второй выбран в PLAN как повторяемые раунды наблюдения сигнала с переключением
observe/compare; его реализация пока не начиналась.

Оценить нужно: понятны ли правила первого процесса, видна ли связь решения с
проверкой, и соответствует ли показанный результат этому ограниченному шагу.
Реплик владельца о приёмке этой реализации пока нет. Следующий необходимый этап
для закрытия — отдельная свежая физическая G5 и приёмка в HOME. Вся M1 ещё не готова.
