# Создание Activity с сохранением шагов

Владелец 17 октября 2026 года: «Да, согласую это изменение ядра.
Запускай исполнителя на Sol 6.1 для создания Activity с сохранением шагов
и продолжением после обрыва, потом независимую проверку. Показывай результат;
следующие задачи пока не запускай.» Это разрешение реализации, не приёмка продукта.

Откройте обычный Pi в нужной папке, один раз подключите `/zaratustra` и опишите
дело обычными словами. При создании новой Activity адаптер обязательно включает
сохраняемые шаги; отсутствие или false у model hint `setup` не отключает защиту.
Для существующей Activity обычная coding-работа сохраняет штатные инструменты.

Модель выбирает содержание, структуру и размер полезного шага. Общий versioned
Method `activity-setup/1` не навязывает интервью, журнал, расписание или шаблон.
В setup доступны Core-чтения и собственное чтение небольшого UTF-8 файла в выбранной
папке. Shell, произвольный MCP, внешние записи и промежуточный `zara_change` здесь
не исполняются. Если для дела нужен недоступный инструмент, ассистент объясняет
ограничение; прочитанный текст и невыполненное исследование не равнозначны.
Публикация Method/memory требует отдельных допусков: без них допустима scoped
data-предложение, а не подмена действующей общей инструкции.

Один сохраняемый шаг — один Work. `zara_result` только подготавливает metadata;
до Core receipt шаг ещё не сохранён. Actual final Pi сохраняется сначала как
terminal, затем Core одной транзакцией применяет changes, Result и следующий Work
либо адресованный wait. UI подтверждает сохранение только после receipt. Исходный
текст модели не проверяется на качество и может быть виден во время выполнения.
Следующий шаг запускается после этого сохранения; производственный лимит вызовов
не вводится. Ожидающий вопрос и обычный ответ сохраняются между Pi sessions.

После закрытия вернитесь через `/zaratustra`: незавершённый setup определяется
по Core Work/Result/wait. `/reopen` также перечитывает это место. Mapping — только
восстанавливаемый указатель. Retained terminal сначала досохраняется без модели;
готовый Result/child используется повторно. Невалидный старый terminal не переписывается.
Без terminal разрешено возобновить только подтверждённый final-only setup: Core
атомарно запрещает старой Attempt менять состояние и поднимает generation.
Неизвестный исход, actions и расход остаются в истории. Поздние callbacks относятся
к исходному сообщению/Attempt, включая соседние tool calls после route.

Выход не является cancel. Явная отмена завершает запуск и сама не возобновляется.
Обычные coding Work с возможными внешними эффектами не получают этот safe renewal.
Профиль — гарантия доверенного адаптера и его собственных инструментов; это не
OS sandbox против стороннего кода с теми же правами пользователя.

Core/App 0.4 использует data protocol2 без новых таблиц. Обновление создаёт
проверенный снимок и атомарный marker; IDs, версии, refs и история сохраняются.
Старый Core0.3 отказывает до изменения protocol2. Обычная совместимая повторная
публикация runtime остаётся идемпотентной. Это техническое обновление формата,
а не семантическая миграция содержимого и не пользовательский backup workflow.

Проверки SDK используют вымышленный localhost provider; они доказывают lifecycle,
не содержательную полезность реальной модели. Живая демонстрация и независимая
проверка точного freeze остаются отдельными действиями root. Весь permanent-use
пакет этим документом не объявляется принятым.
