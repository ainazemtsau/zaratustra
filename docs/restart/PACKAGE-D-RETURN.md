## Delivered path

Ordinary chat stages exact human input durably before public C2 delivery. Core is
the only continuation authority. For a new free request a generic model discovery
chooses or reuses an Activity and its meaningful agreement. C8 atomically commits
its typed changes, routing result and exactly one scoped continuation Work, while
preserving the original cursor and pending raw input. The useful Work receives the
original messages, selected exact Activity and applicable memory. Its result and
corrections remain linked to that Activity; different requests can select another.
There is no subject keyword router, fixed project form or mandatory interview.

Discovery is internal and its JSON is not a user answer. Normally a free new turn
costs discovery plus execution; both consume the same finite inherited reservation
budget. An addressed reply continues its existing scoped Work. Late input before
first dependent dispatch explicitly refreshes to discovery in history without
rewriting the old scope. A child with insufficient remaining resource stays paused
with pending input and no prepare/dispatch. Reopen consumes retained terminal
first. Unknown sends are not automatically repeated; no continuation resets cost.
Existing Method versions/adaptations remain intact; defaults use versioned
conversation-routing/1 and conversation/2. Core validates identity, references,
rights, CAS and scope; the model owns subject meaning and useful content.

Interactive answers address the displayed exact wait; free messages do not consume
it. Cancellation atomically saves the human input boundary. No new human input,
including subsequent tool-origin messages, leaves a cancelled turn stopped. A later
human request creates separate work, retaining prior claims/reservations/fences.
No model can grant rights or accept the owner's result. Malformed terminals remain
retained known invalid_request evidence, without host-crash resend.

Pi is the sole installed full client. Native pi-chatgpt uses explicitly selected
Pi-owned OAuth storage, the public Responses endpoint, store=false and stream=true.
There is no API-key fallback, Codex token extraction or substituted model/account.
The official selected-model SDK compatibility option preserves reasoning effort
without unsupported configuration_update input. The native max_tokens/context values are SDK/model configuration, not proven
server output-token bounds. The selected SiWC route documents max_output_tokens
as unsupported; successful HTTP acceptance never establishes its enforcement.
The owner explicitly selected calls-only on 2026-10-17: «Да, ограничиваем число
обращений — продолжай (рекомендуется)». That choice carries no guaranteed hard
token/money ceiling. The corrected native profile must explicitly declare
native_resource_mode=calls-only and omit the unsupported token field through
Pi's supported compatibility option. Old native profiles are refused before
auth/process access, rather than silently reinterpreted. Existing local SDK
sizing validation remains; API-key behavior and Core resource admission stay unchanged.
Physical forwarding bounds inference sends, including Pi retries. OAuth service
refresh is separate. Bearer echoes are redacted before Pi/capture with original
hash/size and an explicit redaction marker. OAuth errors are sanitized before
retention. Diagnostics never include conversations, raw provider bodies or secrets.

Artifacts are durable immutable complete bytes with typed record refs. Backup holds
writer exclusion through inventory, SQLite snapshot, copied artifacts and atomic
publication. Restore verifies hashes/sizes/inventory, SQLite integrity/FKs and the
known typed reference graph, including historical pinned copies, schema-declared
refs and continuation lineage. It preserves valid historical versions independently
of mutable heads/statuses/inputs. Ordinary JSON/text is not heuristically traversed.
Restore publishes a new identity/epoch/credential, fences Attempts and leaves no
runnable intents; the new copy is quarantined. There is no activation command.
Original intermittent Windows publication holder remains unknown. Reproduced
sharing/access denial is mitigated with a finite 2 s Windows 5/32/33 retry of the same
stage; permanent/unrelated errors fail and may leave a held partial directory.
