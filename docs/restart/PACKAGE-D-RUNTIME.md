## Новая установка

Архив: `evidence/package-d/final-f80180a/zaratustra-next-d-f80180a-windows-x64.zip`.
Распакуйте его вне Git checkout. Внутри находятся оба wheel, пять wheel зависимостей,
проверяемые SHA-256 и установочные скрипты. Старый продукт и его данные не нужны.
Установка создаёт пустое новое пространство, без примеров и импорта.

Поддержанная проверенная среда: Windows x64, PowerShell 7, uv, Python 3.13.7
(SQLite 3.50.4). uv может установить выбранный Python, если его ещё нет.
Для разговора отдельно нужны Node 22.19.0, Pi 1.3.0 и собственная авторизация Pi.
Зависимости Python устанавливаются из архива без обращения к индексу.

Пример после распаковки; выберите два ещё не существующих пути вне Git:


## Разговор и продолжение

В открывшемся входе напишите свой запрос обычными словами. При каждом запросе модель
получает исходный ввод, предыдущие ответы, каталог записей, выбранную Method
и применимую память. Она выбирает содержание Activity и необходимую организацию.
Код не выбирает тему и не навязывает интервью. Полезность этого поведения остаётся
предметом отдельной живой проверки.

Ответ на показанный вопрос в интерактивном входе адресуется именно этому вопросу.
Обычное свободное сообщение не закрывает иной wait. `/exit` закрывает клиент.
Повторный запуск Start.ps1 читает то же пространство; локальная история Pi не
нужна. После законченного turn можно писать следующий запрос без JSON или сценария.
После отмены повторный запуск остаётся остановленным до нового человеческого
сообщения; новое сообщение создаёт отдельную Work, сохраняя старые резервы и fences.

Новый свободный запрос обычно требует discovery и полезное исполнение: модель
выбирает или сохраняет Activity, затем выполняет запрос в её scope. Оба шага
учтены в одном конечном ресурсе цепочки; discovery JSON пользователю не показывается.
Адресный ответ продолжает существующую Work. Если остатка недостаточно для
следующего шага, Work остаётся paused, а исходный ввод pending.

`CallLimit` — конечный общий предел inference sends Work и её продолжений. Перед Attempt
резервируются два вызова; proxy пропускает не более двух физических sends,
включая внутренние повторы Pi. Неиспользованная верхняя граница консервативно
остаётся зарезервированной. Новая Attempt или next_work не сбрасывает общий расход цепочки.
Владелец явно выбрал ограничение числа обращений: native профиль должен содержать
`native_resource_mode: "calls-only"`. Гарантированного максимума output tokens или
стоимости у выбранного subscription доступа нет. Поле `max_output_tokens` не
отправляется через штатный `supportsMaxOutputTokens:false`. Сохранённый `max_tokens`
служит локальной настройкой SDK/context sizing, а не серверной гарантией. Его
прежняя локальная проверка минимума16 сохранена. Старые native профили без явного
режима отвергаются до чтения auth/запуска, их нельзя молча переобозначать.
Настройки API-key пути не меняются. Один Work chain по умолчанию ограничен8sends;
все tool-follow-up и повторы Pi входят в тот же физический предел.
При неизвестном исходе автоматической повторной отправки нет. Не меняйте профиль
у уже запущенной Work; явный `--refresh-basis` предусмотрен для известного
непригодного ответа в прежнем остатке. Расширение лимита старой Work не реализовано.

## Собственный доступ Pi к Luna

Codex CLI и Pi авторизуются отдельно. Используется современный OpenAI provider Pi
через public `api.openai.com/v1/responses`, `store=false`, `stream=true`.
Pi сам читает и обновляет выбранный OAuth файл; приложение не копирует credentials.
API-key fallback, legacy backend-api и смена оплаченной модели не применяются.

Если собственный Pi ещё не подключён, выполните в отдельном терминале:

~~~powershell
$env:PI_CODING_AGENT_DIR = 'C:/Users/Anton/.pi/agent'
pi
~~~

Внутри Pi: `/login openai` → **Sign in with ChatGPT** → согласие в браузере.
Доступ именно к `gpt-6-luna` зависит от аккаунта. Источники официальной схемы:
[Sign in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in/),
[models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference/).
Pi сам обслуживает выбранный OAuth ресурс. Приложение использует штатную
настройку совместимости SDK для этого доступа; выбранный reasoning сохраняется
на уровне запроса. Наличие авторизации и доступ к модели проверяются отдельно от
полезности ответа. История технических проверок и ограничений кандидата находится
в PACKAGE-D-RETURN.md и evidence.

OAuth refresh — отдельный служебный запрос, не inference send. Служебные ошибки
OAuth выдаются безопасным кодом; их потенциально секретный raw body не экспортируется.
Provider echo известного bearer удаляется до Pi и capture, с hash исходных bytes
и явной пометкой redaction. Диагностика не включает raw разговоры и auth-файлы.

## Диагностика, файлы и резервная копия

~~~powershell
$entry = 'C:/ZaratustraTrial/runtime-D/env/Scripts/zaratustra-next.exe'
& $entry --data-root 'C:/ZaratustraTrial/data-D' diagnostics
& $entry --data-root 'C:/ZaratustraTrial/data-D' diagnostics --destination 'C:/ZaratustraTrial/preview.json'
& $entry --data-root 'C:/ZaratustraTrial/data-D' artifact --file 'C:/ZaratustraTrial/chosen-file.bin'
& $entry --data-root 'C:/ZaratustraTrial/data-D' backup --destination 'C:/ZaratustraTrial/backup-D'
& $entry --data-root 'C:/ZaratustraTrial/restore-D' restore --file 'C:/ZaratustraTrial/backup-D'
& $entry --data-root 'C:/ZaratustraTrial/restore-D' diagnostics
~~~

Preview показывает только фиксированный безопасный набор: версии, integrity/FK,
режим и количества. Передачи куда-либо нет. `--destination` сохраняет именно
показанный preview в новый локальный файл. Artifact возвращает digest; записи
могут ссылаться на удержанные bytes через `artifact_refs`. Backup содержит SQLite,
полный inventory удержанных artifacts и их точные bytes; он исключает одновременно
пишущие клиенты. Повреждённые или неполные копии отвергаются. При временном Windows sharing/access
отказе публикация тех же staged bytes повторяется не более двух секунд. Постоянный
отказ остаётся ошибкой; конечная копия не объявляется готовой. Если внешний процесс
удерживает файлы, после отказа может сохраниться каталог `.partial-*`.

Restore создаёт новое пространство/instance, новый epoch и credential. Старые
допуски недействительны; Attempts fenced, продолжения не исполняются. Результат
остаётся **quarantined**, пригодным для чтения публичным Core API и диагностики.
Команды активации в этой поставке нет: включение исполнения потребует отдельного
выбора единственного активного экземпляра и прекращения старого. Backup/restore
не обещают отменить уже выполненный внешний эффект или превратить unknown в no-send.
