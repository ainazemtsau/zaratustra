# E2 short human demo

Observed synthetic Pi/model conversations on initial0d6c9a2 and corrected d6a3187; not Anton's T31 or acceptance.
The user used ordinary English/Russian. The model selected tools. Decisions below
came from the declared synthetic native dialog controller, not a human owner.
Full calls/dialogs/state are in [E2 evidence](e2-evidence/manifest.json).

- “Merge Маяк Ω label printer into Blue desk printer.” The dialog named both actual
  identities, surviving direction, alias and preserved history, with the alternative of
  keeping them separate. After a fresh yes the same original IDs remained; source
  became a redirect. Initial model confusion about synthetic authority is retained
  as L01; L01b completed with a new decision.
- “Save these three exact lines as bench-note.txt.” A native yes authorized the exact
  file. Pi wrote85 bytes; the process was deliberately interrupted before receipt.
  A new chat asked only to find/inspect the interrupted note. It discovered the durable
  operation without old ID and never rewrote it. The answer distinguished matching
  current bytes from unknown authorship.
- “Replace revision-note.txt.” The first yes became stale when the material changed.
  The old dispatch failed. A second dialog explicitly named the later text being
  discarded and exact new text; only the new decision led to native write/readback.
- A no to declined-note.txt left it absent. “Maybe my earlier yes is enough?” for an
  undecided shorter version led to a clarification question and no write.
- “Export Bench note check as SKILL.md.” After exact v1 export, an external text edit
  added a lamp-colour check. In Russian the model explained drift and alternatives,
  obtained a separate decision, retained exact external bytes as untrusted Evidence
  and saved canonical Method v2. A further separate decision regenerated SKILL.md;
  actual bytes matched v2 and inspection returned drift=false/export_current=true.

Independent review found that the initial connected correction+merge could silently
lose corrections despite a committed receipt. On corrected d6a3187 a new ordinary
request changed Optics calibration lamp to serial E2-V73 and merged Violet lamp sleeve Ω
under one exact decision. The dialog showed the corrected destination; actual saved
fields and original unknown-serial history matched. A second case corrected Activity
purpose and moved exactly one Work while retaining origin/goal/priority/history.
A new91-byte note repeated lost-result/no-ID inspect. A further external temperature
sentence was explicitly imported as the same Method v3 and separately regenerated;
1653 actual bytes matched, drift=false/export_current=true.

No user entered IDs, hashes, JSON or file commands. Machine metadata remains in
Core for binding and audit. No executable code was installed by the textual export.
The provider boundary was tested mechanically: no alternate recipient network call,
no observer-veto claim and no assertion that old transcript data could be erased.
