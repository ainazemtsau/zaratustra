# Общее инженерное review выпуска 0.18.0, 2026-09-27

Это один авторский обзор связного пакета после реализации и установленной
пробы. Он не является независимой приёмкой владельца. Рассмотрены Sleep,
AD05, Activity, установленный Pi, ремонт/Pulse, backup/restore и обновление.

| Контракт и наблюдаемый случай | Влияние | Разбор и проверка |
|---|---|---|
| Sleep: три допустимых Source при `limit=2` | Старый `exhausted=true` терял третью запись после сохранённого курсора | Пагинация учитывает реально потреблённые строки; две страницы и перезапуск курсора PASS. Отбор остаётся отдельным от доставки и анализа |
| Program/Composite AD05: подготовка не равна применению | Текст Method или флаг мог бы ложно объявить программу установленной | Сохранённый exact build и SHA, Decision/Grant, атомарный пакет, отдельная физическая запись и Core confirm; stop/restore сохраняют события. Профильная и установленная пробы PASS |
| Activity split/merge: прямой перенос не давал допуска существенной перестройки | Крупная реорганизация обходила Candidate/ValidationPlan/Decision | Добавлен типизированный ActivityChange в тот же цикл; проверены область Decision, права `activity.write`, точные ревизии, stop и возврат. Установленный Pi+CLI и профильная проверка PASS |
| Создание Activity из Change пакета первоначально проверяло только `method.write` | Можно было создать область без права `activity.write` | Перед применением и возвратом пакета добавлена проверка `activity.write` для пространства, помимо адресных проверок Work/Activity; затронутые проверки PASS |
| Обычный Pi запускался с `--no-tools` | Development Attempt не мог реально прочитать и править выбранный файл | Штатные native `read/write/edit/bash` и инструменты Zaratustra включены по умолчанию; новая установка показала этот набор в обычном запуске |
| `select` мог выбрать разошедшуюся копию с тем же space ID/номером ревизии | Возможная потеря уже известных операций | Сравниваются исходные operation ID и fingerprint; старую схему/историю выбрать нельзя; узкая регрессия и установленное восстановление PASS |
| Repair/Pulse и неизвестный ответ provider | Повтор по догадке дал бы слепой внешний эффект | Read-only Pulse отделяет наблюдение от повреждения; `repair` указывает assignment/invocation/wait и безопасное действие. Неизвестный исход синтетической пробы сохранён, ресурс fenced; исправление внешней истины не симулировалось |
| Полный gate: неизменённый конкурентный тест `entry/test_catalog.py` один раз вернул строку ошибки вместо успешного designation | Первый прогон не был PASS | Адресный повтор теста прошёл; повтор полного gate прошёл 751/751. Файлы `entry` не менялись, причину единичного исхода без сохранённого кода ошибки установить нельзя; наблюдение оставлено в RESULT |

Сильные границы: программа пишет только файл выбранного ресурса с проверенным
prior/desired SHA; частичная файловая установка не делает пакет active;
старая несовместимая программа не открывает новую схему; backup восстанавливают
в новый каталог и новый epoch. Проверки не утверждают смысловую пользу текста
или полноту неизвестных внешних последствий.

Профильные проверки после узких правок: Activity/Program 5 PASS, Ruff/mypy,
26/26 импортных границ, wheel build; установленная Activity-проба дала
`apply → stop → restore`, Pulse findings=0. Повтор полного gate после одного
непрошедшего конкурентного теста: 751 PASS и сборка. Факты обоих прогонов —
в `RESULT.md`. Финальный wheel после переустановки прочитал ту же историю;
его backup/restore/recover/select проверены на новом epoch 2 без находок Pulse.
