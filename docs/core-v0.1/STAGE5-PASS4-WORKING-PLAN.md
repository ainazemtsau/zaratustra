# Stage 5, проход 4 — рабочий план

1. Установить общую границу обслуживания вокруг выдачи DBOS, действующего
   назначенного Pi и интерактивного Pi. После закрытия Pi и DBOS проверить, что
   нет активного управляемого исполнителя; при неопределённости отказать с
   диагностикой, сохранив состояние и `unknown`.
2. На этой границе собрать два SQLite-снимка и управляемые Pi-файлы; записать
   версии, границу состояния, состав и хеши в общий манифест. Публиковать пакет
   лишь после проверки всего состава; прерывание оставить незавершённым.
3. Проверить адресное удаление Core, DBOS, Pi и затронутых пакетов, карантинный
   restore с новой эпохой и сохранение вопросов, остатка, расхода и `unknown`.
4. Воспроизвести конкурентные SQLite lock/I/O и прерывание обслуживания;
   исправить конкретные дефекты. Выполнить затронутые регрессии, установленный
   Core → DBOS → Pi probe и `tools.check --deliver`. Записать пределы и сделать
   локальный коммит без приёмки Stage 5 за владельца.
