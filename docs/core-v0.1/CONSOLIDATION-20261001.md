# Одна основная версия Zaratustra — 1 октября 2026

## Решение и происхождение

Владелец согласился использовать последнюю реализацию Core/Activity как основу,
сверить нужные возможности прежнего main, объединить разработку и перенести
проверенный результат в main: «Окей, давай так и сделаем».
Его текущий запрос на использование: «ChatGPT и телефон плюс локальные агенты»;
первое личное направление — Health. Это запрос на подключение, а не свидетельство,
что эти подключения уже работают.

Обе реализации происходят от `9913786eacb9c95ce103e29a21fa1e89dbdbd070`
(15 сентября). Прежний main продолжился десятью коммитами 16–17 сентября до
`c73d039eb3f318893820b2b5e7c73f69092ccbd8`: Home, журнал, skills, web requests,
переносимое файловое хранение. Реализация Core v0.1 началась 22 сентября от
того же основания и развивалась отдельно. Это смена реализации, которую не
довели до общей основной ветки и не отразили вовремя в Direction OS.

Выбранный исходный код: `3303b20e391a73d58016557ea7ac45ee32f57394`, включающий
все изменения first-use до `ed540107d9f228ae87db53e4ec6627a94418cc19` и
исправления удаления `1b888389d43733e34736391dbf6bdac80fbd37ca`.
До объединения прежний main сохранён как `codex/home-line-retained-20261001`.

## Что означает объединение

Объединяется история Git с двумя родителями; рабочее дерево остаётся выбранным
Core. Это намеренный выбор реализации, а не построчный merge несовместимых
источников данных. Все коммиты прежнего main остаются предками общей ветки.

Единственный актуальный предметный источник данных — SQLite Core v0.1.
DBOS хранит техническое состояние исполнения отдельно, как предусмотрено
спецификацией. Старый Home/file-first backend не подключается параллельно.
Утверждённая [спецификация](Zaratustra_Core_Specification_v0.1.md), A1/O15,
прямо допускает новое пустое предметное состояние, замену прежней реализации
и отсутствие совместимости старых API/storage. Её байты не меняются.
Сохранившиеся модули прежней реализации 0.17 и ранние планы — исторический
контекст; обычный текущий вход — `zara-core`, а не старые `zara`/`zara-agent`.

Пользовательские данные не мигрируются и не удаляются объединением Git.
Выбор версии программы и перенос данных — разные операции. Установка уже
обновлена пакетом исправления удаления; эта консолидация меняет документацию
и происхождение основной ветки, не схему установленного пространства.

## Сверка пользовательских возможностей

| Возможность прежнего main | Текущая реализация и следующий шаг |
|---|---|
| Найти направление и продолжить работу | Activity list/read, Work, Method, Result и продолжение после перезапуска реализованы в Core; использовать этот путь. |
| Записывать материалы и сохранять историю | Source/Knowledge, адресные ревизии, Memory, результаты и история операций реализованы. Это не совместимость прежнего journal API. |
| Изменять порядок работы и сохранять методы | Method, Sleep, Change, решения, применение/остановка/восстановление входят в текущий Core. Старые process skills не переносятся отдельным backend. |
| Локальный агент работает с одним состоянием | Обычный Pi — проверенный текущий адаптер. Отдельные актуальные адаптеры Codex/Claude ещё не заявлены готовыми; старые skills используют прежний API. |
| Обсуждать с ChatGPT с телефона и сохранить результат | Старый GitHub/web-request обмен обращается к старому журналу. Его подключение к Core отсутствует; нужна адаптация к Source/Work и проверка настоящего доступа ChatGPT. Не выдавать старые Project instructions за новое подключение. |
| Home-группы, связи регистраций и файловая синхронизация | Не являются обязательной совместимостью Core v0.1. Нужные сценарии нескольких Activity нужно реализовывать над одним Core, не возвращая второй источник данных. |
| Резервная копия и восстановление | Текущие `backup`, `restore`, `recover`, `select`, `upgrade` и управляемое удаление используются через Core. Исправления удаления и сохранения чистых копий включены. |

## Проверки и предел вывода

Для пакета исправления до консолидации прошли native gate (758 тестов, Ruff,
mypy, 26 импортных контрактов, сборка), затем 13 адресных тестов поздней
поправки и повторная сборка. Исходный и отдельно установленный wheel прошли
обычный Pi knowledge/handoff probe с локальным синтетическим провайдером.
См. запись «Проверка ночного аудита и безопасность удаления» в
[RESULT](../../RESULT.md).

Консолидация не меняет исполняемые файлы относительно выбранного Core.
Merge `8539bf0d46d3a9cfc70c4f2168eea1cf4f7de4da` имеет обоих ожидаемых
родителей. Git подтвердил ancestry обеих линий и неизменность всех файлов,
кроме README, AGENTS, RESULT и этой записи. Спецификация совпала точно.
Native hygiene, структура отчёта и `git diff --check` прошли. Атомарный push
и authenticated readback GitHub подтвердили опубликованный main `8539bf0`
и сохранённую старую ветку `c73d039`. Эти проверки
не являются повторной приёмкой всех функций, binding G5 или доказательством
готовности ChatGPT/телефона. Program rollback после отзыва Decision остаётся
отдельной неподтверждённой находкой ночного разбора.

## Следующая функциональная работа

Подключить ChatGPT/телефон к тому же Core и проверить один настоящий цикл
Health: прочитать выбранный контекст, обсудить, сохранить запрос/материал,
принять его локальным агентом и увидеть сохранённый результат после перезапуска.
До выбора рабочего транспорта и проверки аккаунта не объявлять этот цикл готовым.
Результат разработки возвращается в Solmax; закрытие задачи Direction OS требует
своих действующих критериев. Git merge сам по себе их не закрывает.
