# Установка и обычная работа с Core

Этот документ описывает продуктовый путь, не адреса или настройки конкретного
экземпляра. Исторические установочные отчёты не заменяют текущие команды.

## Компоненты

- Python 3.13 и uv для Python-пакета.
- Обычный upstream Pi из PATH и совместимый Node; проверены Pi 1.0.4 / Node 22.19.0.
- Закреплённый SQLite 3.53.3; на Windows явный проверенный DLL можно указать при setup.
- Собственный конфиг провайдера и аккаунта. Секреты остаются в предусмотренном
  провайдером хранилище, не в коде, примерах или Project Instructions.

Соберите/установите wheel по README. Выполните `zaratustra setup --help`, чтобы
увидеть точные текущие параметры. `zara-core` остаётся совместимым maintenance entry.

## Новое пространство

Выберите отдельные пути для конфигурации, Core и рабочего ресурса. Следующий пример
использует относительные пути и требует выбора реально доступной модели:

```powershell
zaratustra setup `
  --config .\install\config.json `
  --space .\data\space `
  --workspace .\work `
  --new-space `
  --sqlite-dll .\runtime\sqlite3.dll `
  --provider-profile codex-sse `
  --provider-base-url https://chatgpt.com/backend-api `
  --provider-id openai-codex `
  --model-id "<supported-model-id>" `
  --reserve-units 0
zaratustra bind --config .\install\config.json
zaratustra verify
zaratustra
```

Это пример для поддерживаемого Codex SSE profile, не обещание доступа к конкретной
модели. SQLite DLL и обычный Pi должны быть подготовлены до setup. Для существующего
Core не используйте `--new-space`; не создавайте новую базу при диагностике старой.
Другой поддерживаемый профиль выбирается явно по контракту CLI.
Отсутствующий `--limit-units` оставляет учёт без локального spending stop.

## Выбор установки и запуск

Приоритет конфигурации: явный `--config`, затем `ZARATUSTRA_CONFIG`, затем сохранённая
launch-reference в пользовательском профиле. `bind` выбирает уже существующий конфиг,
не переносит данные и не меняет модель. `verify` показывает версию программы,
идентичность/схему/epoch Core и выбранный runtime.

Обычный `zaratustra` запускает Pi после `CONNECT`. `/zara-work` выбирает Activity/Work;
`/zara-status` показывает адресное состояние и расход; `/resume` продолжает сохранённую
беседу. Выбор работы не означает разрешения принять её результат.
Модель на один запуск можно переопределить через `--model <model-id>`.

Обычный Pi берётся из PATH при каждом запуске. Явный `--pi-runtime` остаётся opt-in
для отдельной совместимой установки, не вторым обязательным Pi. История Pi сессий
и пользовательские credentials отделены от ресурсов wheel.

## Работа и память

Попросите создать/прочитать Activity, подготовить Work или способ исполнения обычным
языком. `zara_activity` работает с направлениями, `zara_development` — с Method/Work,
Sleep/Change и их контролируемыми действиями. Это не закрытое меню задач пользователя.
Routine preparation/evidence saves используют текущие права Core без лишних UI prompts;
приёмка, Decisions, права, удаление и application/stop/restore остаются отдельными
подтверждаемыми действиями. Наличие инструмента не создаёт права.

`zara_memory` сохраняет источники, Claim, Analysis и Handoff, читает exact revisions
и ищет допустимую память. `zara_result` публикует сам полный deliverable в объявленный
слот выбранного Work; обычное пояснение не заменяет результат. Acceptance отдельно.

Назначенные Work запускаются по существующему Pi RPC / DBOS пути с точными Attempt,
pin и admission checks. Сохранённый вопрос читается/отвечается через обычный интерактивный
Bridge. Unknown после возможного внешнего эффекта не превращается в безопасный повтор.

## Обновление программы

Завершите процессы Zaratustra перед заменой package/shims на Windows. Для уже
установленного uv tool:

```text
uv tool install --force --from <new-wheel> zaratustra
zaratustra verify
zaratustra
```

Повторный setup/bind и правка старого START.ps1 не нужны. Существующий конфиг, модель
и Core сохраняются. Команда `upgrade` относится к схеме Core, не к обновлению программы.
Храните прежний wheel для обратной установки; не путайте смену программы с restore
предметных данных. Если installer отказал из-за занятого файла, сохраните полный вывод
и проверьте фактическую версию/состояние среды, прежде чем объявлять обновление успешным.

## Обслуживание

`inspect` и `pulse` — model-free inspection; `backup`, `repair`, `restore`, `recover`
работают через предусмотренные maintenance contracts и проверки epoch/authority.
Чтение findings не является разрешением автоматически менять или удалять данные.
Публичные Core операции и receipts — единственный поддержанный путь изменения состояния;
прямое редактирование SQLite или второй реестр не являются способом восстановления.

## Внешние инструменты

См. [интеграции](../integrations.md). При доступном GitHub внешнему чату не нужен
постоянно обновляемый файл Project. Код читается из выбранной опубликованной ветки;
локальные/неопубликованные сведения уточняются выборочно. Возвращённый материал сначала
сохраняется целиком; предложение и разрешение выполнить его остаются разными вещами.
