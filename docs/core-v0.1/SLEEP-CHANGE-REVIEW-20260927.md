# Общий инженерный review пакета Sleep/change — 2026-09-27

Объект: schema 11, Sleep Method/Work, операции изменения, Pi/DBOS путь,
ревизии, права и обслуживание. Проверялись предметные переходы и обычный
сценарий, не смысловая полезность синтетических выводов.

## Конкретные найденные нарушения и исправления

1. Назначенный дочерний Attempt первоначально получал только чтение Core.
   Воспроизведение: запустить Sleep child через DBOS/Pi и попросить сохранить
   частичный `SleepState`; записи через обычный Pi не происходило. Это
   блокировало результат Sleep. Назначенному Pi доступны типизированные
   `zara_memory` и `zara_development`; Bridge ограничивает запись собственной
   семьёй Sleep Work, не даёт назначенному Attempt принимать Decision или
   применять кандидата. Сценарий проверен фактической квитанцией в пробе.
2. Дочерний Work после применения новой версии Method первоначально получал
   в HTTP контексте только свою краткую цель. Воспроизведение: создать новый
   составной Work с Method v2 и запустить оба дочерних Attempt. Тогда модель
   могла исполнить старую инструкцию. Bridge теперь доставляет закреплённый
   Method, обязательства и план родителя в ContextManifest дочернего Work;
   проба проверяет два фактических HTTP body с инструкцией v2.
3. Общая версия Binding и несколько областей применения могли конфликтовать:
   остановка одного приложения ставила на паузу всю Binding версию. Это
   прерывало разрешённое срабатывание другой области. Текущее состояние
   Binding теперь выводится из оставшихся действующих Decision; наложение
   двух активных допусков на одну область отклоняется. Trial считает только
   собственные фактические срабатывания приложения.
4. Возврат Method мог объявить `restored`, хотя прежняя версия уже не была
   доступна или не имела текущего допуска в той же области. Это давало
   ложный успех. Возврат теперь сверяет точную предыдущую версию и её
   действующий допуск в области; при недостающем основании оставляет `partial` с
   причиной, позволяя повторить восстановление после исправления основания.
5. Удалённое основание позднего отрицательного результата могло оставаться
   в JSON истории приложения. Это выдавало запрещённые данные через чтение
   истории. Ребро evidence связывает результат с точным источником; удаление
   санирует событие, receipt/replay и загрязнённые backup.

## Итог review

Все пять находок исправлены в этом пакете. Затронутые проверки и полный gate
записаны отдельно в `RESULT.md`. Инженерный review не означает приёмку
качества метода, всего Core или внешних эффектов. Реальная модель, платный
provider и личные данные не участвовали.
