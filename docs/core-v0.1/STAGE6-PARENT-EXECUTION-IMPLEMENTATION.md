# Stage 6: исполнение составного родителя в том же Work

Статус: реализация отдельного среза для одного технического review. Это не
приёмка schema 7, прохода 3 или Stage 6. Исходный коммит — `b3ccf15`;
техническое review части 3.10 закрыто отдельно до начала среза.

## Контракт

Явный `upgrade_parent_execution_space` переводит одноразовое schema 7 space в
schema 8 с неизменными прежними DDL/checksum. Новые таблицы хранят точное
закрепление собственной Attempt к плану и Method, а также доказательство
публикации выхода с адресами Attempt, закрепления и Artifact. Старые поля
сериализуются как раньше: `parent_outputs`, `own_pins`, roleless `role` и
`parent_result` отсутствуют в старых payload. Новые варианты на schema ≤ 7
получают `unsupported_schema`.

План объявляет производителя собственного слота как Work. Он не закрепляет
конкретную Attempt, поэтому новая допустимая Attempt того же Work не требует
редакции плана. Публикация и подтверждение записывают её точные адреса.
Результат чужой, огороженной или замещённой более новым поколением Attempt не
может подтвердить обязательство или позволить принятие. Новая публикация
переоткрывает прежнее подтверждение; новое основание записывается отдельно.

Корневой и вложенный составной Work используют существующие назначение,
launch claim, Pi RPC и DBOS. Общий Core gate перепроверяет точный план,
Method, выданных предков, входы, basis и права перед эффектом. Редакция плана
ограждает собственную Attempt. Уже отправленный вызов остаётся `unknown`,
с удержанием ресурса и резерва. Дочерний путь, рольные обязательства,
необязательные дети и отдельное принятие остались доступны.

`CompositionView.own_pins` и Pi `/zara-status` показывают адреса собственной
Attempt и рольное/собственное обязательство без копии текста плана или
обоснования. Чтение точного доказательства, replay, receipt, backup format 2,
карантинный restore и адресное удаление идут через существующий Core path.
При удалении зависимого Artifact основание подтверждения и принятия
санируется; независимые Work и адресная история сохраняются. При удалении Work
его собственные закрепления и доказательства удаляются вместе с Attempt.

## Проверки сеанса реализации

Новые Core-регрессии покрывают schema 7 отказ, положительный A/B/P, повторную
Attempt без редакции плана, старый результат до новой публикации, ограждение,
unknown с удержанием, чужое evidence, вложенный G → N → P с открытым
необязательным соседом, backup/restore и последовательное удаление. Синтетический
localhost probe через обычный Pi/DBOS дал **3 HTTP**: после A — 1, B — 2,
P — 3; подтверждение, принятие, Pi status, backup/restore и удаления — 0
дополнительных. Это проверки реализации, не независимого reviewer.

Первый полный Windows `tools.check --deliver` на кодовом пакете — **PASS**:
**687 тестов**, 215 файлов format-clean, строгий mypy для 189 файлов, Ruff,
**21** импортный контракт, sdist и wheel. Журнал:
`_scratch/parent-execution-deliver.log`. Предварительные попытки gate
остановились на формате нового теста и двух `None`-проверках mypy; после
исправления полный gate прошёл. Это собственный прогон реализации.

Сохранённые probes на отдельных одноразовых spaces также прошли: Stage 5 —
**2 HTTP**, Stage 6 — **3 HTTP**, schema 7/pass 3 — **4 HTTP**. Отчёты:
`_scratch/parent-regression-stage5`, `_scratch/parent-regression-stage6`,
`_scratch/parent-regression-pass3`.

Установленный wheel проверен вне checkout из точного чистого кодового коммита
`3d6adcce5ab4c561a1c4204d341e72d32272d3f5`:
`source_tree_dirty=false`, Python 3.13.7, SQLite 3.53.3, **3 HTTP**,
`outside_checkout=true`, wheel SHA-256
`C4CB44C45C6CAC1D3AB4D32F553EADD812E5F4D6AA3805FB89464D9D51C71C75`.
Отчёт: `_scratch/parent-installed-3d6adcc/report.json`.
Первая установленная попытка того же сценария на `8dfeeb7` выполнила 3 HTTP,
но обёртка не завершила отчёт из-за отсутствовавших полей `python` и
`sqlite`; отчётная правка вошла в `3d6adcc`. Это не независимое review.

Повторный полный gate на окончательном документальном пакете указан в `RESULT.md`.
Технический review среза остаётся открытым до независимой проверки.

## Границы

Использован только синтетический localhost provider и одноразовые пространства.
Реальные модели, пользовательская миграция, проход 4, собственный dispatcher,
PR и приёмка не начаты. `database is locked` и `rpc_transport` остаются
открытыми наблюдениями; успешный probe не объявляет их устранёнными.
