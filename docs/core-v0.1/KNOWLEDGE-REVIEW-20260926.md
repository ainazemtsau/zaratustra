# Первичка/Claim/память/контекст/handoff — общий технический review

Дата: 2026-09-26. Объём: один законченный пакет schema 10 и обычного Pi.
Это review автора реализации после полного gate, **не независимая приёмка**
владельцем и не review всего первого продукта. Следовал
`DELIVERY-POLICY-20260926.md`: проверял обычное чтение/изменение/удаление,
права, точные версии, передачу документа и фактический provider body.

## Конкретные находки и закрытие

1. **Поиск мог раскрывать закрытые совпадения.** В первой версии `restricted`
   зависел от пропущенной скрытой строки, а числовые FTS/edge cursor выдавали
   внутренний rowid. Актор с адресным Grant мог различить наличие скрытого
   слова/связи без права чтения. Теперь ограничение определяется областью
   его прав независимо от совпадений; курсоры содержат только адрес уже
   показанной записи/ребра. Тест сравнивает выдачу закрытого слова и
   отсутствующего слова для адресного читателя.
2. **Ответ Pi мог пережить удаление цитируемой первички.** Тело tool result
   сохранялось повторной Source без `derived_from`; последующая санация
   оригинала не достигала копии. Теперь тело tool result не сохраняется
   (Core уже адресует действия квитанцией), а захваченный ответ Pi указывает
   предъявленные источники, поиск и обязательный контекст. Адресное
   удаление в тесте делает ответ недоступным и очищает FTS.
3. **Поздний handoff мог сопоставиться со старым Artifact.** Проверка
   актуальности включённых оснований смотрела только knowledge records.
   После изменения Artifact можно было записать `matched` со старой
   редакцией. Теперь проверяются и обычные Core/subject revisions; тест
   воспроизводит отказ `stale_basis`.
4. **Навигационная связь имела только закреплённую цель.** Контракт памяти
   допускает отдельно точную использованную редакцию и динамическое
   открытие текущей цели. Добавлен явный `target_mode`, исходная точная
   ссылка остаётся в provenance, а чтение соседей разрешает текущую версию
   и показывает закреплённый адрес. Тест меняет Artifact после создания
   связи и проверяет оба адреса и обратную навигацию.

## Проверки и остаток

Полный gate реализации на законченном первом кодовом состоянии: **735 PASS**,
формат, Ruff, mypy **198 файлов**, импортные границы **23/23**, sdist/wheel и
report structure. Он предшествовал четырём поправкам выше; это не повторный
полный gate. После них: затронутые Core/Pi bridge тесты **12 PASS**,
формат/Ruff/mypy, импортные границы, сборка, обычный Pi с фиктивным localhost
provider для первички/Claim/Work/handoff/ручной compaction и Binding регрессия.
Точные финальные проверки и SHA — в `RESULT.md`.

Новых блокирующих находок в указанном объёме после исправлений нет.
Настоящая модель не выбирала смысл Claim, внешний участник не получал
документ, paid API не вызывался. Локальная Pi-проба подтверждает операции,
адреса, реальные тела запросов и разделённые стадии, а не содержание
будущего ответа человека или модели. Исходный FTS5 даёт лексический поиск;
достаточность русского нахождения устанавливается в пользовании.
