# Development with OpenSpec

OpenSpec 1.16.0 is pinned as a development dependency. Install dependencies with
`npm ci`. Commands use the local executable through the package script.
Generated skills show commands as `openspec <args>`. Execute those examples as
`npm run openspec -- <args>` in this repository. Keep the generated skill bodies
owned by OpenSpec. The repository formatter excludes these generated upstream
files so an OpenSpec refresh preserves their original content.

```powershell
npm run openspec -- --version
npm run openspec -- list
npm run openspec -- list --specs
```

## Owner workflow

1. Explain the problem in chat. The agent reads the relevant code and explores
   the decisions with you.
2. Ask for an OpenSpec proposal. The agent prepares the change's proposal,
   requirements with scenarios, design and implementation tasks.
3. Review a short Russian explanation and approve the change scope.
4. Ask the agent to implement the approved change. Tasks include focused checks
   and record the work that actually completed.
5. Review the implementation and check results, then integrate the change.
   Sync its specifications and archive the completed change.

The CLI validates artifact structure. Behavior is established by source review,
focused tests and any specifically required runtime observations.

## Codex and Pi

The core profile installs six workflows for both assistants. Codex reads generated
skills from `.agents/skills/`. Pi reads `.pi/skills/` and prompt templates from
`.pi/prompts/`. Both use this repository's shared `openspec/` artifacts.

| Action                      | Codex skill                | Pi prompt       |
| --------------------------- | -------------------------- | --------------- |
| Discuss and investigate     | `$openspec-explore`        | `/opsx-explore` |
| Prepare a change            | `$openspec-propose`        | `/opsx-propose` |
| Implement approved tasks    | `$openspec-apply-change`   | `/opsx-apply`   |
| Revise change artifacts     | `$openspec-update-change`  | `/opsx-update`  |
| Sync completed requirements | `$openspec-sync-specs`     | `/opsx-sync`    |
| Archive a completed change  | `$openspec-archive-change` | `/opsx-archive` |

In Codex desktop the Skills selector can invoke the same named skills. Ordinary
chat requests can also ask the agent to use a named workflow.

Optional workflows such as `verify` and stepwise `continue` are available through
OpenSpec profile configuration. This setup uses the core profile. Review can be
requested directly against the proposal, scenarios, tasks and implementation.

## Repository files

- `openspec/config.yaml` carries context and project-specific artifact rules.
- `openspec/specs/` grows with verified capabilities as changes are completed.
- `openspec/changes/<name>/` holds a proposal, delta specs, design and tasks.
- `.agents/skills/openspec-*` and `.pi` integration files are generated by OpenSpec.

Commit the configuration, generated integrations, specifications and change
artifacts alongside the relevant code. Use a feature branch and review the
specification and implementation together. An unfinished change stays visible
with its actual outstanding tasks.

Generated skill bodies are refreshed by OpenSpec. Put project rules in AGENTS.md
and `openspec/config.yaml`. Treat an OpenSpec version upgrade as its own reviewed
change because `openspec update` uses the machine's selected global profile.
