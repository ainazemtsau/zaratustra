# Activity: процесс и данные

Продукт 0.22.0; явное обновление Core 14 → 15.

## Обычная работа

Опишите цель и привычный способ работы в Pi. Например: записывать наблюдения
в течение дня, приносить их через несколько дней, планировать неделю и обсуждать
результаты за месяц. Ассистент уточняет решения, влияющие на работу, предлагает
основу и сам проектирует её. Пользователь не выбирает таблицы или форматы файлов.

Вопросы и реальные ответы сохраняются. После подготовки отдельный этап проверяет
весь пакет. Исправления причин сопровождаются новым полным ревью. Максимум пять
начатых ревью на явно продолженный проход; перезапуск сохраняет счёт и версии.
Обязательного пробного цикла нет. Activity может работать только с документами
или иметь журналы, планы и анализ. Доменный шаблон не обязателен.
См. [принципы Activity](activity-principles.md).

## Что сохраняет Core

| Запись | Значение |
|---|---|
| Source | Оригинал сообщения, исследования или дневника |
| DataFormat | Поля, единицы, точность, статусы и идентичность |
| DataEntry | Объект, событие, план, документ или анализ в точной версии формата |
| ActivityStructure | Проверенный процесс, процедуры, подборки и инструкции |
| Artifact | Результат Work с основаниями |

Формат — конечное дерево: текст, логическое значение, целое, Decimal, дата,
время с часовым поясом, перечисление, ссылка, объект или список. Код схемы не
исполняется. JSON Schema описывает поддержанный язык. Decimal передаётся строкой;
Core проверяет точность без скрытого округления. Отсутствующее поле, неизвестное
значение и ноль различаются.

Дата события отличается от даты получения оригинала. Период имеет начало и
исключённую правую границу; календарь процедуры задаёт часовой пояс. План не
становится фактом. Новое событие получает новый адрес; исправление добавляет
редакцию прежней записи. Внешняя идентичность сохраняется.

Назначение материала (`working`, `basis`, `intake`, `execution`, `representation`)
отдельно от прав и актуальности. Частично разобранный оригинал остаётся видимым
поступлением. Служебная запись не становится автоматически рабочей памятью.

## Публичный доступ

`zara_data` предоставляет контракт и операции:

- `describe_structure`, `list_formats`, `read_format`;
- `create_entry`, `correct_entry`, `ingest_batch`, `read_entry`, `history`;
- `query_entries`, `aggregate_entries`, `working_set`;
- `start_procedure`, `procedure_status`, `due_procedures`.

Тот же интерфейс доступен через адаптер `data` и `zaratustra data contract/apply`.
Пользователю обычно достаточно объяснить задачу ассистенту.

Для публикации результата выбранной Work ассистент получает точную схему
каждого выходного слота в контексте и через `zara_result` (`read` или `contract`).
Программный каталог — `output_publication_contracts(WorkState)`. Для типизированного
выхода он описывает существующий `DataOutputEnvelope`: `result` — строка,
`entries` — точные ссылки на сохранённые редакции данных. Требования к текущему
формату, производящему Attempt, области Work и снимку процедуры проверяются Core.
Каталог не разрешает операции и не заменяет эту проверку.

Отклонённый выход сообщает стабильные коды и пути полей через
`OutputValidationError.issues`. Pi передаёт их ассистенту без потери подробностей.
Исправление формы результата не меняет исходные записи и не принимает Work
за владельца. Повтор той же ошибки публикации останавливает текущий модельный
цикл; сохранённые данные остаются доступны.

Выборка фиксирует точные редакции. Связанные записи входят в основания, но не
становятся дополнительными строками расчёта. Каталог и расчёт имеют страницы.
Сумма, среднее, минимум, максимум, число и последнее значение вычисляются кодом.
Версии форматов и единицы не суммируются вместе. Известные, неизвестные и
отсутствующие наблюдения показаны отдельно. Полный состав не доказывает, что
человек записал весь период.

Новые записи меняют актуальность снимка, сохраняя исходные значения. Анализ с
такой выборкой становится устаревшим; код не переписывает смысловой вывод.
Подборка «одна запись» при двух подходящих планах показывает конфликт.

## Процедуры и продолжение

Процедура объявляет цель, параметры, выборку, операции, выходы, способ запуска и
ресурс. Календарь поддерживает день, неделю и месяц; событие оценивается по входам.
Процедура может предложить работу или разрешить запуск. Закрытое Pi новых этапов
не запускает; отдельного календарного сервиса нет.

`start_procedure` сохраняет намерение с ключом, параметрами и периодом до сбора
входов. Затем создаёт точный снимок и обычную Work. Повтор ключа восстанавливает
тот же запуск после смены дня или сессии. Изменившиеся входы позволяют подготовить
новое основание; действующая или неизвестная отправка предотвращает параллельный
повтор. Повтор на прежних входах требует `rerun_of` и сохранённого основания запроса.
`zara_data(mode=run, run_id=...)` исполняет Work через обычный назначенный Pi/DBOS
с выбранным профилем и моделью. Переключения на платный API нет.

JSON-результат типизированной Work содержит точные записи, снимок, полноту,
ограничения и текст результата. Core проверяет формат, Activity, Work и Attempt
перед публикацией и принятием. Сохранение не означает принятие владельцем.

## Изменение Activity

`change_structure` сохраняет адрес существующей Activity, прежние Work и историю.
Предложение компилируется до ревью. Включение проверяет те же версии, права и
прежний текущий указатель. Изменённый ответ или пакет требует нового ревью.

Новая Work получает новую структуру. Начатая сохраняет старую точную версию;
Work до схемы 15 продолжает прежний контекст. Остановка запрещает новые запуски;
возврат указателя не удаляет данные и редакции. Удаление основания убирает
зависимые копии, сохраняя независимую старую настройку. Права перепроверяются
через внутренние связи и промежуточные Artifacts.

## Обновление

Завершите открытые процессы, обновите пакет, затем выполните:

```text
uv tool install --force --from dist/zaratustra-0.22.0-py3-none-any.whl zaratustra
zaratustra upgrade
zaratustra verify
zaratustra
```

`upgrade` делает backup и явно обновляет выбранный Core; чтение не мигрирует.
Личную Activity пользователь пересоздаёт отдельно. Экспортные writers этой
поставкой не меняются. Dashboard, sync и обязательные шаблоны не добавлены.
Типизированные версии и машинно читаемые контракты дают основу будущим интерфейсам.
