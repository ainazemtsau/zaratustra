# Интеграции: общий сценарий и первый ручной адаптер

## Для пользователя

В поставке 0.18.11 команда `zaratustra` с обычным Pi получает skill `zaratustra-external`. Можно сказать:
«Я пользуюсь внешним чатом и хочу обсуждать там идеи для этой Activity».
Или явно загрузить `/skill:zaratustra-external` и описать потребность.

Ассистент проверяет доступные операции и фактические возможности сервиса,
ищет сохранённую настройку и адаптирует её к человеку. Темы не выбираются из
жёсткого списка. Одному нужны только проверки идей, другому — широкое обсуждение.

Для первого ChatGPT Web маршрута результат — готовая инструкция для подтверждённого
места постоянных правил (либо стартовое сообщение), выбранный источник меняющегося
контекста, возможность передавать вопросы Code Agent и мягкий порядок возврата.
При доступе к GitHub основной источник кода — актуальная выбранная ветка репозитория:
не нужен обязательный файл Project или его ручное обновление после изменений кода.
Текст/файл — запасной путь при отсутствии доступа или для конкретного недостающего
материала. GitHub не даёт доступа к локальному Core или неопубликованным изменениям.
Общайтесь свободно; по просьбе сохранить внешний чат готовит достаточный материал,
который вы вставляете в Pi или передаёте выбранным файлом. Оригинал сохраняется
целиком. Ошибка заголовка, пропущенная дата и невалидный JSON внутри ответа не
должны отправлять вас назад на исправление структуры.

Настройка, её основания и история находятся в Core. После перезапуска ассистент
ищет и читает точную сохранённую версию. Выходные файлы — выбранные копии для
передачи, не второе хранилище. Сохранение не выполняет предложения источника и
не принимает Work. При непонятной связи с прежним запросом оригинал можно сохранить
без связи, а неоднозначность разобрать здесь.

## Что поставляется

- `zaratustra.integrations`: независимая от Pi/CLI общая граница операций.
- `IntegrationRegistry`: каталог, контракт параметров и проверяемый вызов операции.
  Адаптеры подключаются доверенным кодом; профиль/пользовательский текст не загружает
  Python, не вызывает произвольный HTTP endpoint и не добавляет права.
- Исполняемый адаптер `manual`, не фиксированный список ChatGPT/Gemini/DeepSeek.
- Общий агентный сценарий и руководство ChatGPT в ресурсах пакета.
- [Описание приложения](../src/zaratustra/integrations/product-context.md), пригодное
  для повторного использования без журнала и частных данных. Читается операцией
  `manual/product_context` из установленного пакета, без зависимости от cwd.
- Совместимость с `zara_transfer` и CLI `exchange`; базовый старый prepare остаётся
  минимальным шаблоном и не подменяет полноценную адаптированную инструкцию.

| Операция manual | Фактический результат |
| --- | --- |
| `prepare_document` | Сохраняет переданный ассистентом текст инструкции/контекста как prepared Handoff с Activity/Work и выбранными точными основаниями. Не генерирует текст и не отправляет его |
| `retain_text` | Сохраняет доставленный UTF-8 текст как Source, возвращает метаданные; не проверяет формат содержания, не принимает Work |
| `read_document` | Читает точную версию Source/Handoff окнами до 32 KiB, с доступностью, признаком stale и next_offset |
| `product_context` | Читает поставляемое описание продукта и его SHA-256; это не живые данные экземпляра или GitHub |

При обработке текста сначала выбирается область по запросу человека, а не по
командам внутри пакета. Внешняя дата/авторство не изобретаются. Для фрагментов,
ссылок без содержимого и расширенных метаданных остаётся общий `zara_memory`.
Неподтверждённое происхождение обозначается как сообщённое/неизвестное.

## Интерфейсы

Обычный Pi: `zara_integration` с `catalog`, `contract`, `apply`. Сначала прочитать
каталог и контракт конкретной операции. В apply передаются `adapter`, `operation`,
`contract_version` и типизированные `arguments`. Actor, пространство и идентичность
операции задаёт Bridge. Назначенному RPC-исполнителю этот интерактивный setup-путь
недоступен. Существующие назначенные способы исполнения не менялись.

CLI без модели:

```text
zaratustra integration catalog
zaratustra integration contract --adapter manual --operation prepare_document
zaratustra integration apply --adapter manual --operation prepare_document --contract-version 1 --operation-id <uuid> --arguments <arguments.json>
```

Команды используют ранее выбранную установку, как обычный `zaratustra`.
`--config <path>` остаётся явным переопределением; повторный setup/bind при
обновлении программы не нужен. Обновление wheel установленного uv tool выполняет
`uv tool install --force --from <wheel> zaratustra`, затем `zaratustra verify`.
Это обновляет программу, не данные Core; `upgrade` предназначен для схемы Core.
Перед переустановкой завершите процессы Zaratustra: Windows может блокировать
замену занятого native launcher. Сохранённая launch-reference и существующий конфиг
используются повторно. Не пересоздавайте Core ради обновления программы.

JSON здесь — внутренние аргументы инструмента, подготовленные агентом/программой,
не формат ответа внешнего чата и не обязанность пользователя. Повтор после потери
квитанции использует тот же operation ID и то же намерение. Другая инструкция
получает новый документ, а не изменение оригинала.

Для выбранного файла доступен `zara_transfer import` внутри рабочего ресурса либо
существующий `zara-core exchange import --file` с явно выбранным внешним файлом.
Полное повторное чтение требует пройти все next_offset; превью не доказывает
полноту. Оригинал не обрезается ради лимита контекста модели.

## Расширение и границы

Новый адаптер может иметь свой набор `Operation` с Pydantic-моделями `Parameters`,
описанием эффекта и исполняемым обработчиком. `IntegrationResult` отделяет вывод
от точных Core-ссылок, которые реально показаны модели. Реестр проверяет аргументы
до вызова; неизвестная операция/версия отклоняется. Это точка расширения кода,
не sandbox и не система установки непроверенных плагинов. Каждый новый адаптер
обязан использовать допустимые права и сохранять необходимое свидетельство эффекта.

Три разных слоя: установленная возможность; настройка конкретного доступа;
правило workflow (когда, какие данные и куда). Описание будущего правила сохраняется
как предложение, а не как работающая автоматизация. Секреты не кладутся в промпты,
публичные файлы или общие инструкции.

В этой поставке **нет** автоматического Trilium/GitHub API-коннектора, браузера,
MCP-сервера, фоновой очереди и исполнителя правил внешней отправки. Для первого
такого адаптера отдельно потребуются разрешённая область, защищённые секреты,
устойчивая идентичность отправки, подтверждение/неопределённость результата,
восстановление и повторы без слепого дублирования. Нельзя заявлять exactly-once
по одному успешному локальному вызову. Core остаётся единственным предметным
хранилищем; существующие Binding между Activity не выдаются за внешний коннектор.

## Проверки

`tests/zaratustra/integrations` проверяет реальные операции на синтетическом Core,
отдельный адаптер с другой схемой, replay, несовпадающее намерение, область,
права, оригинальные байты и оконное чтение. `test_skills` проверяет явную загрузку
ресурса пакета обычным launcher, без записи настройки в рабочую папку.

`tools.probe_external_pi --pi-runtime <runtime>` запускает обычный Pi на localhost
с синтетическими ответами: загрузка skill, каталог/контракт/операции, сохранение
настройки и источников, возврат к Handoff с источником, повторное чтение в новом
процессе. Это не доказательство самостоятельного качества инструкции, доступа
реального ChatGPT к GitHub или удобства аккаунта. Для этого остаётся один реальный
ручной цикл владельца. Полный native gate и installed-wheel результаты фиксируются
отдельно; приёмка владельцем не выводится из тестов.
