# Начатая Work сохраняет свой пакет при обновлении установки

Готова техническая реализация привязки пакетов. Process и его Work запоминают
точную версию; изменение установленных пакетов не переписывает начатую работу.

| Действие в вымышленном примере | Наблюдаемый результат |
|---|---|
| Привязать пакет 1.0.0 к Process и Work | Одна атомарная запись, revision 3→4; права Work прежние |
| Установить рядом пакет 2.0.0 | Старая Work продолжает использовать 1.0.0 |
| Убрать 1.0.0, оставив только 2.0.0 | Отказ в пакетном продолжении; состояние и история прежние |
| Подставить несовместимую версию контракта или состояния | Отказ без записи |
| Попытаться перепривязать начатую Work на 2.0.0 | Явный отказ; автоматической миграции нет |
| Вернуть 1.0.0 и подтвердить точный результат | Result и следующая Work, revision 7→8; обе сохраняют 1.0.0 |
| Создать отдельный новый Process с 2.0.0 | Он связывается и продолжается с 2.0.0 |

Пакет предлагает продолжение, а Core отдельно проверяет права и точный запрос.
Само предложение пакета не может записать результат. Отсутствие пакета не
закрывает владельцу разрешённый доступ к истории и административным операциям.

Полная проверка: **173 теста PASS**, сборка, типы, форматирование и шесть
ограничений импортов. Проверены восстановление трёх контрольных состояний,
откат сбоя транзакции и сохранность прежних записей при явном обновлении формата.
[Полный вывод](evidence/check-deliver.txt), [результат сценария](evidence/summary.json),
[инструкция повтора](REPRODUCE.md), [технический отчёт](../../RESULT.md).

Это этап жизненного цикла пакетов. Семь возможностей контракта, два полных
процесса и их общий обзор остаются следующими отдельными работами. M0 partial.
Фактическая приёмка этого результата владельцем и свежая независимая G5 ещё
не получены; закрытие T2/M1 этим отчётом не заявляется.
