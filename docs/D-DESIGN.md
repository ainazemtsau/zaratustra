# D engineering decisions

The accepted C base is e24b2fda; the owner authorized D with “да”. No future result
acceptance, independent D PASS, complete R1 or T31 is inferred. One executor only.

| Mechanism                                                | Missing guarantee and chosen reuse                                                                                                                                                                                 | Boundary and removal                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Concept/Entity validation and small registered relations | Zod checks fields; ordinary domain checks enforce current typed refs and the final multiple-parent acyclic Concept graph. Prompts cannot enforce atomic graphs.                                                    | No universal graph engine, ontology, property inference, identity guessing or workflow DSL. Real merges/redirects and semantic bulk changes remain unavailable pending E approvals. Rename preserves ID and revisions.                                                                         |
| Canonical Knowledge                                      | Existing records/revisions/Changes retain states, grounded sources, conditions, explicit validity/observation times and supersession.                                                                              | Entity stores identity, never a parallel property/fact bag. The model distinguishes changed conditions, errors, examples, conflict and identity clarification, and revises affected plans.                                                                                                     |
| SQLite FTS5 and ordinary SQL                             | Two built-in indexes: English Porter/unicode61 working text and unicode61 authentic names/aliases/identifiers without stemming. Literal quoting escapes FTS grammar; typed filters and bound SQL supply structure. | No translator/NLP/embedding/reranker/second model, raw SQL or raw FTS; no prefix support. Exact authentic-name matching is a separate flag. No dependency addition. [FTS5 contract](https://www.sqlite.org/fts5.html).                                                                         |
| Derived indexes, barrier and rebuild                     | SQLite updates canonical revisions, FTS, memberships, effective access, sequence and receipt in one transaction. A checked sequence/table barrier rejects unavailable search.                                      | Rebuild touches derived indexes only. Out-of-protocol same-account SQLite/file writes are unsupported. No stale index may be presented as current by supported commits.                                                                                                                        |
| Managed access                                           | Trusted CallContext scopes gate every record/version plus transitively required references. A record depending on restricted content is conservatively hidden. Technical rows are filtered before paging.          | Default workspace scope; trusted setup can supply restricted:read/write via ZARATUSTRA_SCOPES. The model has no principal/scope tool parameter. Restricted source imports inherit restriction; no OS isolation claim.                                                                          |
| Bounded pages and signed continuations                   | SQL limits/keyset ordering avoid whole-memory prompt loads. HMAC binds cursor query/order, effective access, visible generation and position.                                                                      | Per-Core cursor key; a new process restarts pages. Hidden-only changes do not change a lower-scope generation. Query generation calculation reads permitted metadata internally; unlimited-scale latency is not claimed.                                                                       |
| Current snapshot and trace                               | Pi context hook refreshes existing owned data. Work premises expose current Knowledge refs/revisions/states requiring read, rather than general fact injection.                                                    | Snapshot <=12,288 bytes; omitted Work gets must_read. Cards omit prose snippets rather than stripping conditions. Trace keeps query/filter, refs/versions, bytes, truncation, errors and timing, max 512 rows; no normal provider-prompt mirror.                                               |
| Schema 2 to 3                                            | Existing SQLite VACUUM INTO protocol verifies a consistent pre-migration copy, materials, domain refs and post-migration integrity. Existing canonical rows stay exact.                                            | Schema 3 makes the old e24b2fda writer reject the store. Receipt-bound repair handles a crash before manifest replacement. No replacement empty DB, general user backup/restore or archive capability. [Node 22.19 SQLite](https://nodejs.org/download/release/v22.19.0/docs/api/sqlite.html). |

Working record text and search formulations remain English; original Russian Evidence,
names and identifiers remain exact. Derived English representation points to original
Evidence/revision. Unknown valid_from/valid_to/observed_at remain null or absent for
legacy records; migration never replaces unknown time with a write timestamp.

The trusted profile and selected-provider denial remain from accepted C. No ordinary
read/save approval platform, new runtime, installer, ORM or dependency is introduced.
The existing dev braces advisory remains separate and open.
