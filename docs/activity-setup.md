# Первоначальная настройка Activity — 0.20.0

## Как пользоваться

Обновите программу из проверенного wheel обычным способом вашей установки, затем
выполните `zaratustra upgrade` для явного перехода существующего Core к схеме 14.
Обычный запуск: `zaratustra`. В Pi напишите: «Создай Activity для …» и опишите цель.
Начальное подтверждение относится к созданию и настройке именно этой новой Activity.

Ассистент использует выбранные доступные сведения и спрашивает небольшими группами:
какой результат нужен, что происходит сейчас, как вы обычно работаете, что агент
может делать самостоятельно и какие расширения ожидаются. Техническую структуру
проектирует ассистент. Оригиналы запроса и ответов сохраняются сразу в Core как Sources.

После ответов агент вызывает `zara_activity` с `mode=submit`. Можно свернуть Pi:
подготовка, отдельное полное ревью и исправления выполняются, пока окно открыто.
Обязательного пробного цикла нет. Подготовка и ревью не требуют подтверждений
каждого Method или внутренней операции. Когда актуальное полное ревью не нашло
существенных препятствий, продукт включает Activity и показывает первый шаг.
Результаты последующих Work по-прежнему принимаются владельцем отдельно.

## Перерыв и препятствия

`/zara-setup` показывает сохранённое состояние без обращения к модели. Инструмент
`zara_activity` поддерживает `status`, `question`, `answer`, `submit`, `pause`,
`resume`, `cancel` и `retry`; `list` показывает также незавершённые настройки.
`answer` сохраняет полученное пользовательское сообщение, а не пересказ модели.
Повторное сохранение того же сообщения через Pi не создаёт нового ответа.

Закрытие окна прекращает новые этапы, запрашивает остановку текущего Attempt и
сохраняет состояние. Единственная ранее выполнявшаяся настройка возобновляется
при следующем входе после проверок; при нескольких требуется выбрать адрес.
Явная пауза автоматически не снимается. Сохранённый вопрос сначала требует ответа.
После прерывания вопроса назначенного этапа ответ входит в новый точный вход той
же Work; номер начатого ревью сохраняется.

Считаются **начатые Work ревью**, максимум пять, включая первый проход. После
исправлений выполняется новое полное ревью всего актуального пакета. Пять проходов
сохраняются между сессиями; `retry` требует отдельного разрешения на следующие пять,
сохраняя прежние счётчики, версии и расход. Незавершённый или неправильно оформленный
отчёт не означает успеха. Необязательные улучшения остаются в сохранённых отчётах.

Техническая ошибка останавливает этот цикл и сохраняет адресную Work диагностики.
Отправка с неизвестным исходом автоматически не повторяется. Продолжение требует
разобраться с её сохранённым состоянием; запрос `retry` не отменяет неизвестный исход.
Короткая известная конкуренция локального чтения/записи допускает до трёх повторов
обычного кода, без дополнительной модельной отправки.

## Core и точные основания

`ActivitySetupRequest` проходит `apply_operation`: начало, ответ, вопрос, этап,
пауза, продолжение, отмена, завершение и сохранение препятствия. Публичные чтения:
`read_activity_setup`, `list_activity_setups`, `activity_setup_memory`.
Явная миграция — `upgrade_activity_setup_space`, **13 → 14**. Чтение не мигрирует.
Предыдущие API и Activity сохраняются и автоматически не перенастраиваются.

Дополнительные таблицы того же SQLite Core хранят редакции ActivitySetup и адресные
связи. Исходные сообщения — Sources, точные входы этапов и результаты — Artifacts.
История состояния, вопросов, входов, предложений, замечаний и использованных версий
сохраняется. Предложение `ActivitySetupDraft` содержит цель, инструкции, новые Methods,
начальные Work/планы, правила памяти, вопросы и возможные расширения.

Каждый этап получает весь актуальный пакет и JSON Schema своего результата.
Ревью `ActivitySetupReview` должно адресовать точную редакцию предложения и версию
интервью, покрывать цель, обычный путь, историю, продолжение, расширение, поддержку
операций и согласованность. Исправляющий получает полный отчёт и пакет, исправляет
причины и похожие проявления; следующий ревьюер снова получает весь новый пакет.
Core проверяет адреса, типы и полноту отчёта. Семантическое заключение делает агент:
такое ревью не доказывает отсутствие всех будущих проблем.

До готовности обычное исполнение новой Activity блокируется; допускается текущая
подготовительная Work. При включении новые Methods проходят существующие Candidate,
ValidationPlan с сохранённым отчётом, scoped Decision и ApplyCandidate. Координатор
может сделать это только для этой настройки, при текущих правах и актуальных
основаниях. Grants, другие Activity, программный код, публикация и принятие Work
этим разрешением не охватываются.

Включение всех предметных эффектов атомарно в SQLite: неполный набор не объявляется
готовым. Receipts делают повтор после перерыва безопасным. Итоговые инструкции
сохраняются как обязательный Claim области Activity. Правила памяти подключаются
также к её последующим обычным Work через существующий проверяемый кэш. Полный
каталог в каждый запрос не вставляется; закреплённые Method/Work входы не заменяются.

Backup/restore включает новые таблицы. Удаление основания очищает зависимые настройки,
пакеты, методы, инструкции и подготовительные копии; обслуживание удаляет затронутые
управляемые Pi/DBOS копии и резервные снимки. Прочтение производного пакета повторно
проверяет права на оригиналы. Удаление обычной Work само по себе не удаляет настройку.

## Pi и границы поставки

Координатор живёт в Pi-адаптере и использует существующее назначенное исполнение через
обычный Pi RPC и DBOS. У каждого этапа отдельная сессия. Для этапов отключены модельные
инструменты; типизированный итог сохраняется штатной публикацией Artifact. Новая очередь,
служба или собственный модельный движок не вводятся.

Используются выбранные модель и допущенный профиль. Перехода с подписки на платный API
нет. Фактические отправки, включая служебные, учитываются обычным Core-механизмом;
сохранённый статус показывает invocations всех подготовительных Work.

Пакет реализует общий процесс создания Activity. Личная Health, универсальная платформа
ревью и работа после закрытия Pi в него не входят. Новые первоначальные Methods
самодостаточны: их начальные планы используют новые обычные Work своей Activity;
более сложная последующая структура развивается через существующие процедуры изменения.

## Воспроизведение проверки

Все данные вымышленные. `tools.probe_activity_setup_pi` запускается с новым каталогом
и явно выбранным ordinary Pi runtime, использует localhost и не читает credentials.
Он проверяет интервью, исправление, повторное полное ревью, включение, новую сессию,
compact, первую Work, отдельное принятие, фактические ContextManifest/отправки и
обслуживание. Тесты `test_activity_setup.py` покрывают самостоятельные риски состояния,
пяти проходов, scope/прав, атомарности, прерванного вопроса, backup/restore и удаления.
